# Codex 요청 — 액트 2 「모래 폐허」 그림 + 액트 1 새 고유 3종 (2026-10-10, Claude)

설계: [design/13-act2-sand-ruins.md](../design/13-act2-sand-ruins.md) · [design/14-content-flow.md](../design/14-content-flow.md)
사용자 결정(10-10): **액트 2 그림은 전부 코덱스 신규.** 그림이 오기 전까지 Claude가 메이플 리소스 **임시 그림**으로 먼저 구현하고, 들어오면 **CSV 칸만 바꿔** 교체한다.

구현이 단계별이라 **필요한 순서대로** 나눴다 (1단계 → 2단계 → 3단계). 1단계 그림부터 주면 가장 빨리 화면에 붙는다.

## 0. 공통 규칙

| 항목 | 내용 |
|---|---|
| 시점·화풍 | 지금 게임과 같은 **탑다운(위에서 비스듬히)**, 배경 투명, 어두운 고딕 판타지. 액트 2 팔레트: 바랜 모래 황토 · 사암 · 청록 유약 타일 · 화염 주황 · 저주의 보랏빛 |
| 방향 | 몬스터·NPC는 **왼쪽을 보는 그림** (코드가 오른쪽은 좌우 반전) |
| 기준점 | **발밑 가운데** (몬스터가 바닥에 선 위치). 발밑 그림자(옅은 타원)가 있으면 좋다 |
| 저장소 | 월드가 **그룹 월드(OJYYQ)** 다. 반드시 **그룹 저장소**에 올린다 (개인 저장소 그림은 그룹 월드에서 안 보인다) |
| 애니메이션 | 몬스터는 상태 5개 **stand · move · attack · hit · die**. 가능하면 상태마다 **animationclip**(stand·move 4~6프레임, attack 4~6, hit 2, die 4~6). 어려우면 최소 **상태마다 스프라이트 1장**이어도 동작한다 (코드는 둘 다 받는다) |
| 크기 | 아래 px는 원본 기준 권장. 다르면 `monsters.csv`의 `w`·`h`·`scale` 칸도 맞춰 준다 (`w`·`h` = 그림 px, 화면 크기는 `scale`) |
| 색 | 몬스터는 코드가 정예·변종일 때 색을 덧입힌다 → **너무 어둡거나 채도가 극단적이지 않게** |

## 액트 1 새 고유 3종 (지금은 재색칠 임시 그림으로 동작 중)

10-10 의뢰 개편으로 들어간 이름 있는 적. 지금은 `data/named.csv`의 `model` 칸이 기존 몬스터를 가리키고 코드가 색·크기만 바꾼다.

| named id | 이름 | 지금 임시 | 원하는 모습 | 크기(px) |
|---|---|---|---|---|
| `morg` | 썩은 사제 모르그 | 썩은 좀비 초록 재색칠 ×1.35 | 썩어 가는 교단 사제, 부러진 지팡이, 초록 독기 | 100×150 |
| `relic_keeper` | 유물 지기 | 잿빛 망자병 금빛 재색칠 ×1.35 | 녹슨 갑옷의 망자 병사가 금빛 유물 상자를 끌어안고 있음 | 110×150 |
| `blood_priest` | 피의 사제 | 광신 궁수 붉은빛 재색칠 ×1.4 | 피로 물든 로브, 피의 구슬을 띄우는 원거리 사제 | 100×150 |

- 그림이 오면 Claude가 `monsters.csv`에 전용 행(`morg` · `relickeeper` · `bloodpriest`)을 만들고 `named.csv`의 `model`을 바꾼다 (재색칠 `tint` 칸은 비운다).

## 등록 후 할 일 (Codex)

1. 그룹 저장소에 올린 RUID를 위 표의 행·칸에 넣는다 (`monsters.csv` `stand`·`move`·`hit`·`die`·`attack`, `npcs.csv` `stand`). 원본 크기가 다르면 `w`·`h`·`scale`.
2. 바꾼 몬스터 모델만 다시 만든다 (전체 `models` 빌드는 다른 모델을 덮어쓰니 쓰지 말 것):
   `node -e "const m=require('./tools/build/models.cjs');const {load}=require('./tools/build/lib.cjs');for(const r of load('monsters').filter(r=>['jackal','sandscorp'].includes(r.id)))m.buildMonster(r,null);"` (id 목록만 바꿔서)
3. `npm run gen` → `npm test` → 메이커 새로고침 2번 → 그 맵에서 확인.
4. 처리 결과는 `docs/requests/codex-act2-delivery-YYYYMMDD.md`로 남겨 준다 (Claude가 읽고 이어 간다).
