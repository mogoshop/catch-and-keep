## 디자인 방향 (샘플 4종) — 10-23 수정: 「글씨체 바꾸기」가 아니라 「이미지 디자인」

> 첫 v2 지시가 글씨 방향 위주라 글꼴 시안만 나왔다 (사용자: 「폰트만 만들어 낸다」). 원하는 것은 **광고 이미지처럼 구도 · 일러스트 요소 · 연출이 있는 디자인**이다. 글씨는 그 안의 한 요소일 뿐이다.

> 🔁 **2차 결과(10-23)도 수정 전 문서로 작업됐다** — 「V1 CINEMATIC / V2 GAME LOGO / V3 PIXEL / V4 MINIMAL」 4장은 모두 화면 위에 글꼴만 바꿔 얹은 것이라 받지 않는다. 아래 표의 **구도**가 핵심이다. 구도 스케치: `assets/promo-raw-20261023/layout-guide/` (V1~V4 각 1장 + 합본 `layout-guide-4.jpg` — 상자·이름표는 자리 안내일 뿐, 그대로 그리지 않는다).
> **받지 않는 결과**: 실제 화면을 1280×720 전체에 깐 뒤 위쪽에 글씨만 얹은 것 (글씨체가 무엇이든).

실제 플레이 화면은 증거로 **반드시 크게 보이게** 넣되, 그 바깥·위에 디자인 요소를 더한다. 화면 속 도트 자체를 다시 그리지 않는다는 규칙은 그대로다 (화면은 잘라 배치하거나 액자처럼 쓰고, 일러스트는 화면 바깥 · 앞쪽 레이어에).

| | 방향 | 구도 |
|---|---|---|
| V1 | **캐릭터 컷인** | 왼쪽 35~40%에 주인공(해골 왕관 · 재의 왕의 낫) 큰 일러스트 컷인 — 메인 썸네일 ⑤와 같은 그림체. 오른쪽에 실제 화면을 비스듬한 액자로, 위에 큰 글씨 |

방향 공통:
- 「A · B」를 두 줄로 나누면 줄 끝의 「·」는 뺀다 (2차 결과에서 「몬스터의 그림자 추출 ·」처럼 점이 매달렸다). 한 줄일 때만 「·」를 쓴다.
- 글씨는 **화면 높이의 10% 이상**, 320×180으로 줄여도 읽혀야 한다. 「A · B」 두 덩어리는 크기·색으로 위계를 줘도 된다 (글자는 바꾸지 않는다).
- 일러스트는 메인 썸네일 ⑤(`assets/codex-release-thumbnails-v8/exports/05-scythe-and-helmet-1280x720.png`)와 같은 손그림 톤, 또는 게임 도트 톤 — 둘을 한 장에 섞지 않는다.
- 일러스트 속 주인공은 실제 장비와 같게: 해골 왕관 · 푸른 날 큰 낫 · 검은 옷.

## 공통 규칙

- **게임 화면 속 캐릭터·몬스터·소환수·UI는 다시 그리지 않는다** (생성형으로 덮어 그리면 도트가 뭉개지고 실제 게임과 달라진다). 글씨·빛·연기·입자·테두리·어둡게 처리는 이미지 위에 디자인으로 얹는다.
- 게임에 없는 몬스터·장비·효과를 그려 넣지 않는다.
- 지울 것: 오른쪽 위 시스템 아이콘 2개(사람 모양 · 「…」), 「저주받은 상자 · 다가가면 열린다」 이름표, 마나 물약 칸 「0」.
- 남길 것: 아래 생명·마나 구슬과 스킬 칸 (직접 조작하는 게임이라는 증거), 데미지 숫자.
- **피할 글씨**: 기본 고딕 + 두꺼운 외곽선 + 바깥 발광 조합 (v1에서 촌스럽다는 평). 명판·리본·큰 상자로 글씨를 감싸지 않는다.
- 금지: 디아블로 이름·로고·글꼴·붉은 고딕 로고 흉내, 원작 고유명사, 「고르바스」 이름 (이야기 반전).
- 이름 표기: **「재의 왕」** (재 = ash). 「제의 왕」은 오타다.
