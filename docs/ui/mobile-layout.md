## 기본 공격 단추·끌기 취소 (10-29 · I04)

- **고급 배치 기본 공격** `MobilePad/BasicAtk`: 큰 단추(5번 칸)에 스킬을 넣었을 때만 보인다 (편집 중에는 숨김). 공격 단추 오른쪽 위 (-60, 338), 96×96. 입력 사각형 가장자리 간격은 큰 공격과 10(세로)·S4와 8(가로) — `check_mobile_layout`이 둘 다 8 이상인지 잰다 (I04 ㉠, 10-29 코덱스 위임 승인 · 그 김에 스킬 호 S4 (-176, 430)·S3 (-304, 395)로 왼쪽 6·4). 누르고 있으면 기본 공격을 반복하며, PC 기본 공격과 같은 길(`PlayerAttack.SubmitBasicInput` + `ActionAttack`)을 쓴다. 4칸+큰 단추 기본 공격이 기본 배치다.
- **스킬 끌기 「취소」** `MobilePad/AimCancel`: 스킬이 든 칸을 끄는 동안만 보인다 (기본 공격·빈 칸·편집·「줍기」 때는 아님). 손가락이 위에 오면 진해지고 범위 원이 꺼진다. 그 위(여유 16px)에서 떼면 아무것도 쓰지 않는다 — 마나·재사용·해골 그대로, 모으던 뼈 의식은 버린다. 모든 스킬 칸 중심에서 300px 넘게 떨어져 있어(조준 최대 끌기 200px) 보통 조준에 걸리지 않는다.
- 창 열림·사망·맵 이동·앱 전환으로 끊긴 끌기도 버린다 (`MobilePad.Poll`·`UpdateGesture`·`HandleApplicationFocusOutEvent` → `ClearGesture`). 다른 손가락은 제스처를 뺏지도 시전하지도 않는다.
- 오프라인 상태 검사: `lua tests/quality/mobile_input.lua` (실제 MobilePad·SkillBook 본문). 실제 터치·손가락 가림은 실기기에서 본다.

## 고친 원인

**물약 아랫줄이 잘리고 스킬 호가 어긋남.** 원인은 묶음(Skills·Potions·Shadow)이 stretch인데 부모와 저장 크기가 달랐던 것이다.
- 엔진은 stretch 여백을 저장된 OffsetMin/Max로 정하지 않는다. 「부모 RectSize − 내 RectSize」로 다시 계산한다.
- ShadowHUD 루트는 메이커가 2148×901로 저장해 두었고, 묶음은 1920×1080이었다. 그래서 묶음 전체가 114px 옆, 89px 아래로 밀렸다. 실기기 화면 좌표와 정확히 맞았다.
- 지금은 빌드가 루트와 묶음을 모두 1920×1080, 여백 0으로 쓴다. RewardHUD 루트도 같은 방식으로 고쳤다.

## 넓은 창 (10-29 · 기획서 45 결정 4-A)

4:3 태블릿은 1080 높이 기준으로 보이는 폭이 1440뿐이라, 1380~1560 폭 창 5개의 양옆이 잘렸다. `RootDesk/MyDesk/UI/Hud/WindowFit.mlua`가 모바일에서 보이는 폭이 1632보다 좁을 때만 창을 다시 놓는다. PC와 16:9 휴대폰은 빌드 배치 그대로다.
- 창 바깥 폭(테두리 포함) 상한은 보이는 폭 1440에서 가장자리 16씩을 뺀 값이다. 창 바탕 폭 상한은 1368이며, `tools/build/ui-tokens.cjs` `NARROW`와 같은 값이다.
- 그림자 보관함은 2단을 위아래로 바꾼다. 위는 필터·목록 5줄·쪽 넘김, 아래는 상세 판(모습 · 이름·능력치 · 소환 지정·강화·분해)이다.
- 소지품·상점(거래)·스킬 추천·게임 안내는 오른쪽 칸을 좁혀 폭 1368에 맞춘다. 칸 구성은 그대로다.
- 스킬 창(1400)은 기준 창이라 옮기지 않는다. 바깥 1440이 보이는 폭과 같아 가장자리에 붙는다.

## 검사

`npm test`의 「모바일 HUD 배치」(`tools/check_mobile_layout.cjs`)가 다음을 검사한다.
- 화면 4종에서 요소 37개가 화면 밖으로 나가거나 서로 겹치지 않는가: 16:9, 아이폰 가로, 태블릿 4:3, 20:9
- 빌드 값은 ui 파일에서, 실행 중 값은 위 스크립트 코드에서 읽는다. 자리를 바꾸면 이 검사가 바로 잡는다.
- 같은 자리를 번갈아 쓰는 것은 겹침으로 치지 않는다: 배너/여정 안내, 출구 안내/진행 알림 판.
- 넓은 창 5개는 4:3 화면(1440×1080)에서 다시 잰다. 창이 가장자리 16 안에 드는지, 창 아래 조각이 창 밖으로 나가지 않는지, WindowFit이 옮긴 조각끼리 겹치지 않는지 본다. 값은 WindowFit 코드의 글자 그대로를 읽는다.

**메이커 모바일 미리보기는 배치 확인에 쓰지 않는다.**
- 미리보기는 iPad 4:3이고 화면 가장자리를 잘라서 보여 준다.
- 세션 중에 다시 불러온 UI 그룹은 1080 높이로 배치한다. 같은 그룹 안에서도 방금 켠 요소만 실제 높이로 배치되는 등 엇갈린다 (10-13 측정).
- 그래서 자리는 위 검사로 확인하고, 메이커에서는 기능만 본다: 막대 값, 단추 동작, 안내 줄 줄 수.
