# UI/UX & 조작

## 1. 조작

> **2026-10-06 결정:** 2.5D 탑다운 전환에 맞춰 PC는 **마우스(D2식)를 기본**으로 하고, HUD 버튼으로 키보드 조작으로 바꿀 수 있다. 모바일은 가상 스틱 + 버튼. 점프·발판 하강은 탑다운에서 쓰지 않는다.

### 1.1 PC — 마우스 모드 (기본)

| 입력 | 동작 | 구현 |
| --- | --- | --- |
| 바닥 클릭 / 누르고 있기 | 그 지점으로 이동 (누르고 있으면 커서를 따라감) | `Input/ClickControl` |
| 몬스터 클릭 / 누르고 있기 | 다가가서 공격, 누르고 있으면 계속 공격 | `Input/ClickControl` → 기본 공격 |
| 방향키 | 클릭 이동을 취소하고 키보드로 이동 | 두 방식을 섞어 쓸 수 있다 |
| 우클릭 | (Phase 1) 선택 스킬 시전 — D2의 오른쪽 스킬 | 미구현 |

### 1.2 PC — 키보드 모드 / 공통 단축키

| 입력 | 동작 | 비고 |
| --- | --- | --- |
| 방향키 | 8방향 이동 | |
| Ctrl | 기본 공격 (바라보는 방향) | |
| Z | 그림자 소환 (준비된 것 중 등급·레벨 높은 순) | Phase 0 구현 |
| X | 그림자 전체 회수 | Phase 0 구현 |
| C | 집결 | Phase 0 구현 |
| H | 그림자 보관함 | Phase 0 구현 (I도 임시 허용) |
| A S D F / 1~4 | 스킬 슬롯 / 포션 벨트 | Phase 1 |
| I K U Q M | 인벤토리·스킬·능력치·퀘스트·맵 | Phase 1 |
| Esc | 메뉴·창 닫기 | |

### 1.3 모바일

| 요소 | 내용 | 구현 |
| --- | --- | --- |
| 이동 | 좌측 하단 가상 스틱 (8방향) | `MobilePad/Stick` |
| 공격 | 우측 하단 큰 버튼. 2칸 안의 가장 가까운 몬스터 쪽을 자동으로 바라보고 공격 | `ShadowHUD.MobileAttack` |
| 소환·회수·집결 | 공격 버튼 주변 | Phase 0 구현 |
| 보관함 | 우측 상단 | Phase 0 구현 |

모바일 패드는 `ActivePlatform=Mobile`로 지정해도 PC에서 화면 클릭을 가로채므로, PC에서는 스크립트로 꺼 둔다. 실제 모바일 기기 동작은 아직 확인하지 못했다.

### 1.4 구현 메모 (메이커에서 확인한 함정)
- 기본 PlayerController는 입력이 없으면 물리 계산 전에 이동 속도를 0으로 덮어쓴다. 클릭 이동 중에는 컨트롤러를 잠시 끄고 `MovementComponent`로 움직이며, 멈추면 다시 켠다.
- 메이커 마우스 시뮬레이터는 세션 첫 클릭을 놓칠 때가 있다 (실제 입력과 무관할 수 있음).

### 그림자 보관함 UI 주의

- **무제한 보유**이므로 목록이 길어진다. 정렬(등급·레벨·원본), 필터, 검색이 초기부터 필요하다.
- 한 번에 수백 개를 표시하지 않고 **페이지네이션 또는 가상 스크롤**.
- 약한 그림자를 **일괄 분해**하는 기능이 핵심 UX다. (분해 동기를 살리는 도구)
- 분해 확인 팝업은 정예 이상에만 표시.

### 룬 삽입 UI 주의

- 이 게임에서 가장 큰 UI 작업이다. (룬 v0.2 6장)
- 룬워드 도감(조합 확인)을 두면 UI·콘텐츠 비용이 늘지만 이해도가 크게 높아진다. P2.

## 4. 툴팁

| 대상 | 표시 |
| --- | --- |
| 아이템 | 이름(등급 색), 베이스, 요구 레벨·능력치, 옵션 목록, 소켓 상태, 룬워드 이름 |
| 스킬 | 이름, 레벨, 효과, 다음 레벨 효과, 시너지, 마나·쿨다운 |
| 그림자 | 원본, 등급, 레벨, 스탯, 현재 상태 |
| 몬스터 | 등급, 수식어, 저항 (정보 해금 시) |

툴팁은 서버 데이터에서 만든 **문자열 템플릿**으로 생성한다. 텍스트 하드코딩은 현지화(P3) 시 큰 부담이 된다.

## 5. UX 원칙

1. 전투 중 필요한 정보(생명·마나·쿨다운·그림자 상태)는 화면 하단에서 눈을 옮기지 않아도 보이게 한다.
2. 클릭 수가 많은 반복 작업(분해·승급)은 **일괄 처리**와 **빠른 선택**을 제공한다.
3. 되돌릴 수 없는 행위(룬 삽입, 정예 분해)는 확인 단계를 둔다. 반복 행위는 확인을 생략할 옵션 제공.
4. 모든 UI는 모바일 터치 크기(최소 44px 기준)를 고려한다.
5. 아이템 비교를 쉽게: 장착 중인 아이템과의 수치 차이를 색으로 표시.
