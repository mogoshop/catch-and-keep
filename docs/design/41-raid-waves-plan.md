# 41. 습격 — 사방에서 몰려오는 전투 (2026-10-28)

10-28 사용자: 「맵 진입 때 몹이 전부 배치되나? 트래픽을 생각하면 … 사용자를 중심으로 뱀파이어 서바이벌처럼 계속 몹이 오면 … 한 방향에서 소환물이 몸빵하는 단순한 패턴에서 진화될 것 같다」 → 결정 **A「지금 배치 유지 + 습격 웨이브」**(화면 밖 사방에서 약한 떼 · 플레이어당 동시 상한 25~40 · 연쇄 처치와 연결). 보스 쪽(공용 패턴 8종 · 둥지 토템)은 낮에 구현됐고(531666e), 이 문서는 **몬스터 생성 방식과 습격 웨이브**를 부하·템포·난이도와 엮어 설계한다. 입력은 요청서 `docs/requests/fable-41-brief-20261028.md` 하나.

- 근거는 `파일:줄`. 숫자는 10-28 밤 데이터(커밋 3559d44)에서 읽었고, 시뮬은 `tools/sim_balance.py --diff all`과 그 변형(§3-6, 부록 A)이다. 추측은 「추정」.
- 10-28 밤 사용자 추가 지시 네 가지를 그대로 따랐다. ① 템포는 사용자가 실측 뒤 정한다 → 습격의 템포 영향은 **「±얼마」까지만** 적고, 이속·경험치를 바꾸자는 안은 내지 않는다. ② 1차 목표 「노말부터 클리어」 → **보통 습격은 가볍게(무시해도 손해 없게)**, 악몽·지옥에서 규모가 커지는 구조를 복수안에 넣었다. 악몽·지옥 유인 콘텐츠 전체는 기획서 43 몫이라 여기서는 「습격의 난이도 확장」까지만. ③ 부하는 메이커 측정이 무의미하다 → 동시 상한·약한 떼·텔레메트리 지표로 안전장치를 설계하고 실제 값은 출시 서버 `[TEL]`로 맞춘다. ④ 결정 10개 이내 + 끝에 「코덱스에 요청할 그림」.
- 본문은 게임 안 이름(잿불 들개 · 굶주린 구울 · 해골 폭탄 …)으로 쓰고, 코드 이름은 근거 표기에만 쓴다. 글귀(예고·격퇴 문구)는 §7 후보일 뿐 **승인 전까지 확정이 아니다**.

### 3-1. 습격 웨이브 설계 — 언제 · 어디서 · 무엇이 · 몇 마리 · 얼마나 자주

### 3-6. 템포 영향 — 시뮬 (「±얼마」만)

**방법** — `tools/sim_balance.py`를 그대로 불러 맵마다 습격 항을 얹었다(`scratchpad/sim_raid.py`, 부록 A-2). 떼 = 맵 출현 목록 중 생명 최저 종(무리 우선) · 맵 최저 레벨 · 생명 ×0.5 · 처치 90%(수명 60초 안에 못 잡는 10%) · 떼는 플레이어에게 오므로 이동 시간 없음 · 전투 효율은 사냥터와 같은 0.6(사방이라 더 높을 수 있다 — F 변형 0.75). P60 · 의뢰 경로 한 번 · 보통→악몽→지옥 이어서. **이속·경험치 곡선은 손대지 않았다.**

읽기:
- **보통은 어떤 변형이든 끝 레벨 ±0**, 시간은 +0:34 ~ +3:33. 추천(A3)은 +1:02 = 순수 시간의 0.6%(실제 2~3배면 +2~3분, 추정).
- 악몽·지옥은 떼 경험치 배율에 민감하다 — ×0.25 공통이면 +1~+2, **×0.10·×0.05까지 내려야 ±0**. 시간은 지옥 +4:08(순수 2:15의 3%). 지옥 2파(L)는 +7:23까지 — 43이 유인을 얹을 때 이 숫자를 기준으로 상한을 둔다.
- 곁가지 포함(D)·큰 떼(C)·더 자주(B)는 악몽·지옥 레벨을 +2~+4 밀어 올린다 → 횟수·규모를 늘리려면 **경험치 배율을 같이 내려야** 한다(43 주의).
- 사방 효율(F)이 실제로 더 높다면 시간 영향은 절반이다. 연쇄 처치 보너스(3~10%)는 모델 밖이지만 떼 경험치 ×0.25에 곱해지므로 작다(추정 보통 한 바퀴 +1,000 안팎).

**결론(템포)**: 추천 조합은 **보통 +1:02 · 악몽 +1:52 · 지옥 +4:08, 끝 레벨 ±0**. 이 수치를 넘기지 않는 한 습격은 사용자 실측·템포 결정에 영향을 주지 않는다. 템포를 맞추려고 이속·경험치를 건드리는 안은 이 문서에 없다.
