# 기술 구조 & 데이터

mLua 문법의 검증/미검증 구분은 루트 `AGENTS.md`를 따른다. 이 문서는 구조 원칙이며, 미확인 API는 가정으로만 표시한다.

## 1. 서버 권위 원칙

| 대상 | 서버 | 클라이언트 |
| --- | --- | --- |
| 피해 계산 | O | 표시만 |
| 드롭·추출 판정 | O | 표시만 |
| 인벤토리·룬 삽입·승급 | O | 요청만 |
| 스킬 쿨다운·마나 | O | 예측 표시 |
| 이동 | MSW 기본 방식 | |
| UI 상태 | | O |

클라이언트→서버 호출 방식은 **미확인**이다. Phase 0 step 0-1에서 확인한다. 확인 전에는 요청 함수를 추상화(`RequestXxx`) 계층 하나로 모아 교체가 쉽게 한다.

## 2. 데이터 주도 설계

| 데이터 | 형식 | 위치 |
| --- | --- | --- |
| 룬·룬워드·StatCaps | lua 테이블 | 한 모듈 (`StatCaps` 단일 원천) |
| 스킬·몬스터·아이템 베이스·접사 | CSV (스프레드시트에서 편집) → lua 생성 | `data/` |
| 레벨 곡선·드롭 테이블 | CSV | `data/` |
| 퀘스트·NPC 대사 | CSV/lua, 키 기반 | `data/` |

- CSV→lua 변환은 로컬 스크립트로 하고 결과를 커밋한다. mLua에서 CSV를 직접 읽는 방법이 **미확인**이므로 변환 방식이 안전하다.
- 밸런스 수정이 코드 수정이 아니라 **표 수정**이 되게 한다. 시간이 없는 개발에서 가장 큰 절약이다.

## 3. 저장 데이터 구조

저장소는 `_DataStorageService` (검증: 문자열 저장, 서버 전용). 유저 단위 저장은 **미확인**.

```
Account
 ├─ stash: 보관함 아이템
 ├─ shadows: 그림자 보관함 (데이터 행)
 ├─ currencies: 골드·정수·재료
 ├─ quests: 난이도별 진행
 └─ characters[]
      ├─ level, exp, stats, skills
      ├─ equipment, inventory
      └─ shadowSlots (현재 배치)
```

- JSON 문자열로 직렬화해 저장한다. 크기 한계는 **미확인**. 그림자 무제한 보유는 저장 크기 압박이 크므로 **압축 표기**(배열 + 짧은 키)를 쓰고, 한계 확인 후 상한을 정한다.
- 저장 시점: 변경 즉시가 아니라 **주기(30~60초) + 중요 이벤트 + 퇴장**. 호출 한도 **미확인**.
- 스키마에 `version` 필드를 둬서 마이그레이션 가능하게 한다.

## 4. 서버 부하 예산

| 항목 | 목표 [가정] |
| --- | --- |
| 맵당 플레이어 | 4 |
| 플레이어당 소환수 | 8 (전체 32) |
| 몬스터 AI 틱 | 0.3~0.5초 |
| 소환수 AI 틱 | 0.3~0.5초 |
| 투사체 | 개별 엔티티 대신 판정 즉시 계산 + 연출만 클라 |
| 몬스터 수 / 맵 | 50 이하 [가정] |

MSW의 엔티티 한계·서버 틱 비용은 **미확인**. Phase 0에서 소환수 8×4=32 + 몬스터 50 조건의 부하 시험을 먼저 한다. 통과 못 하면 배치 한도를 줄이는 쪽이 첫 번째 대응이다.

## 5. 치트 방지·무결성

| 위험 | 대응 |
| --- | --- |
| 클라이언트 값 신뢰 | 서버가 재계산 |
| 아이템 복제 | 서버 발급 `uid`, 거래·이동은 단일 처리, 거래 로그 |
| 룬 삽입 취소 악용 | 삽입은 즉시 확정, 롤백 시도는 로그 |
| 이중 보상 | 퀘스트·보스 보상에 수령 플래그 |
| 비정상 이동·공격 속도 | 서버 쿨다운 강제 |

## 6. 로깅·운영

- 중요 이벤트(아이템 생성·소멸, 거래, 룬 삽입, 승급, 보스 보상)는 구조화 로그로 남긴다. MSW의 로그 수집 방식은 **미확인**.
- 이상 징후(분당 아이템 획득 과다 등)는 임계치 로그부터 시작한다.

## 7. 밸런스 도구

- 로컬 스크립트(Lua 또는 Python)로 **전투 시뮬레이터**를 만든다: 입력=스킬/장비/몬스터 표, 출력=처치 시간·DPS·생존.
- 룬워드 14개와 4개 빌드의 DPS를 표로 비교해 과도한 편차를 먼저 찾는다.
- 이 도구는 MSW 없이 돌아가므로 **회사에서 설치가 끝나기 전에도 진행 가능**하다.

## 8. 코드 구조 (초안)

```
Scripts/
 ├─ Shared/   StatCaps, 데이터 테이블, 공용 유틸
 ├─ Server/   ShadowSystem, Combat, Loot, Inventory, Quest, Save
 ├─ Client/   UI, 입력, 연출
 └─ Data/     CSV 변환 결과
```

실제 구조는 메이커·LocalWorkspace 확인 후 맞춘다. (`.mlua` 위치 규칙 미확인)
