# 메이플 리저렉션 품질 후속 — 개선 설계 및 통합 계약
작성: 2026-10-29 / 독립 코드 작업
기준: ed5e4243d0370f80d12543b2439a66f82e5b22df
분류: F01~F11은 결함 수정. 아래 I01~I06·I08은 별도 제품/콘텐츠 정책 제안이다.
Maker 플레이·실기기 입력·사용자 소요시간 측정은 하지 않았다. 모든 시간 목표는 설계 가설이다.

0. 결정 요약

이미 있는 재료를 이해하고 시험하게 만드는 것을 우선한다. 첫 선택의 결과는 빨리 보여 주고, 완성 군단·희귀 조합·후반 운용 전환은 이후에 남긴다. 첫 2시간/4시간은 관찰 시점이며 시간 해금이나 접속 유지 조건으로 사용하지 않는다. 같은 경험 순서를 짧게 나누어 하는 사람과 몰아서 하는 사람이 모두 만날 수 있어야 한다.

이번 구현: 레어 총 옵션 수 계약, 퀘스트 착용 가능 보상, 일일 후보/달성 가능성, 도감 대상/식별자, 업적 묶음 수령, 선택한 강화 설명, 실제 유효 랭크/충전/호령/일반형 소환 요약, 추천 누락. 장비 수치·경험치·드롭률·스킬 포인트·룬워드 허용 등급·소환 편성 정책은 재조정하지 않았다. I04의 작동 조건 안내만 F07 설명 수정에 함께 반영했다. 다른 개선을 구현 완료로 표시하지 않는다.

우선 구현 순서(권장):
1) F 수정 통합 및 Maker 확인 → 2) 첫 장비/선택/보고 왕복 관찰 → 3) 모바일 기본공격 접근+취소와 소환 배치 미리보기 → 4) 대표 맵 하나씩 동선 실험 → 5) 목표 파밍/부분 재련.
새 스킬·새 등급·새 재화·새 출석 시스템은 이 순서의 전제가 아니다.

공통 성공 기준:
- 새 판단 없이 같은 행동만 반복하는 연속 구간이 줄어든다.
- 사용자가 자신의 장비 교체 이유, 전투 방식, 다음 목표를 설명하고 다음 전투에서 차이를 확인한다.
- 4시간 이후에도 다른 변형/전문화/파밍 목표가 남는다.
- 소환·마법·저주혼합 모두 합리적 시작이 가능하다. 세 계열을 같은 비율로 채택시키지는 않는다.
- 선택 경로에 필수 영구 포인트를 숨겨 사실상 전부 돌게 하지 않는다.
- 총 몬스터/보고 횟수를 늘려 새 사건을 덧붙이는 방식은 개선으로 세지 않는다.

1. 최신 코드에서 이미 개선된 점과 남은 경계

data/config.csv: earlyExpLevel=8, earlyExpMult=1.8, shadowFullLevel=10, deployExpandFromLv=12/step5. 초기 경험치와 군단 진입은 이미 앞당겨졌다. 주석의 '약12분' 등 과거 설계 추정은 최신 실측값으로 인용하지 않는다.
UndeadSystem.SpawnTaste + ShadowSystem의 첫 처치 임시 그림자가 이미 있다. 최초 군단 체험을 또 별도 튜토리얼로 제작하지 않는다.
data/quests.csv 1번 '굶주린 굴'은 skp:2+gen:3, 2번 모르그는 deploy:1+unique:1+choice:1, 5번 처형인/상자는 runes:1+choice:2, 9번 우물은 skp:2+choice:3. 초반 보상과 선택 시스템이 없는 상태가 아니다.
SkillOffer는 새 기술/랭크/강화 추천과 영구 선택 보상 창을 함께 쓴다. 별도 대형 추천 시스템은 중복이다.
MapEvents·MapShrine·CursedChest·Nest·의식·유입 풀이 존재한다. 최근 길 위 사건은 기존 빈 이동을 줄이려는 변화다. 최신 플레이 없이 여전히 지루하다고 확정하지 않는다.
Telemetry는 first.load/move/kill/taste/shadow/town/death, 레벨/퀘스트 시각, 맵 체류, 전리품 등을 이미 모은다. 실제 사용한 장비 교체/선택 이유/무판단 반복 구간/DPS는 현재 기록만으로 충분히 알 수 없다.

2. I01 — 레어 품질, 부분 재련, 여섯 등급

근거: ItemData.FillAffixes/RerollMods/RollAffix, data/item_affixes.csv·item_bases.csv·item_uniques.csv·item_sets.csv. 현재 재련은 매직/레어의 전체 옵션을 교체한다. 생성 ilvl과 착용 reqLv는 다른 값이다. F01은 3/4/5개 추첨 비중을 보존하고 고갈한 쪽만 재배분한다. 신발의 접두1종 때문에 접미가 4개까지 나올 수 있는 규칙을 명시한다. 접사 수치/등급을 올린 것이 아니지만 이전 미달품보다 새 제품의 총 성능은 높아질 수 있다. 기존 장비는 다시 굴리지 않는다.

역할 권장안:
일반/소켓: 원하는 소켓·베이스를 찾는 제작 원형. 고급 등급 아래의 쓰레기라는 안내를 피한다.
매직: 적은 옵션의 집중형 중간 선택. 지금은 레어와 같은 옵션값이므로, 상한 인상보다 낮은 조정 비용/집중형 용도를 먼저 검토한다.
레어: 여러 유효 옵션의 조합으로 오래 다듬는 장비. 좋은 조합은 유니크와 경쟁할 수 있어야 한다. 자동으로 항상 현재 빌드의 정답이 되게 만들지는 않는다.
유니크: 특정 운용·상호작용을 선택하게 하는 고유 효과. 모든 부위의 일괄 상위색이 목표는 아니다. 기존 유니크 일괄 하향은 하지 않는다.
세트: 부분 완성부터 도움이 되고, 일부 레어/유니크를 섞을 이유가 있는 수집 목표. 전 부위 세트 강요를 피한다.
룬워드: 재료·소켓·순서를 알면 계획할 수 있는 제작 목표. 모든 무작위 장비를 압도하는 필수 완성품으로 만들지 않는다.

대안 비교:
A 전역 드롭 증가: 살펴볼 물건/판매 작업을 늘리면서 개인 활용 확률을 해결하지 못한다. 현 단계 비권장.
B 현재 빌드 자동 스마트루트: 즉시 쓰기는 쉽지만 전환/혼합·발견을 좁힌다. 일반 드롭에는 비권장.
C 중요 보상의 부위 또는 계열 1회 선택: 일반 파밍의 폭을 남기며 빈 구간만 다룬다. 첫 장비 계약의 후속으로 권장. 이미 choice가 있으므로 새 선택 시스템 대신 기존 카드 UI를 재사용한다.
D 레어 1옵션 교체: 좋은 원형 발견 가치를 남길 수 있다. 아래 작은 실험 후 채택.

부분 재련 실험 계약(아직 미구현):
- 매직/레어만, 고유/세트/활성 룬워드는 제외. 선택한 한 옵션만 같은 부위·ilvl·tier의 합법 후보로 바꾼다.
- 베이스/등급/ilvl/소켓/삽입 룬과 나머지 옵션을 그대로 둔다. 중복 stat은 피한다.
- 새 결과/기존 결과 선택, 비용 사전 표시. 후보가 없으면 비용 소비 없이 거절. 시도 비용은 확인한 시점에만 차감, 수령/클릭 중복 방지는 인벤토리 슬롯+기존 문자열 버전에 결합한다.
- 권장 초기 제한: 아이템당 재련 대상으로 정한 옵션 한 줄만 계속 교체 가능. 모든 줄을 반복 교체해 완벽한 장비를 보장하는 확장은 보류한다. 신뢰할 수 있는 장비 고유 식별자/재련 대상 기록이 필요하므로 기존 문자열 파싱·거래·창고·저장 호환 설계를 먼저 한다. 옵션 수를 '줄'로 표시하려면 현재 합산 mods 구조와 별도 접사 정체성이 필요하다.
- 비용은 현재 전체 재련(레어 ilvl42 1632골드)과 현재 골드 흐름을 기준으로 실험한다. 측정 없이 새 가격이나 새 재화를 확정하지 않는다.

검증/부작용: 주요 빌드의 같은 포인트·장비 예산에서 실제 쓰는 교체/낮은 롤/무관 옵션/상한 초과를 분리. 원형 발견→교체→사용 시간과 총 재련 지출/판매 공급/혼합 빌드 선택을 함께 본다. 모든 레어가 업그레이드인 비율을 목표로 삼지 않는다. 재련 때문에 드롭을 볼 이유가 없어지거나 골드가 의무 비용이 되면 제한·비용을 되돌린다.
이관: 기존 아이템은 그대로. 신규 재련 데이터만 버전을 둔다. 기존 아이템에 무작위 재생성/일괄 능력치 변경 없음.

3. I02 — 룬워드 허용 등급과 기존 장비

근거: ItemData.GetRuneword는 등급 제한 없이 소켓수/정확한 순서/부위를 본다. SocketRune도 등급을 막지 않는다. 문서의 '일반 장비' 설명과 다르다. 현재 35개 레시피를 새로 늘릴 필요는 없다.

A 현행 허용 유지+문서 정합: 가장 이관 위험이 작다. 일반/매직 베이스의 룬워드 경쟁을 명시하고 극단 조합을 검증한다. 기존 장비 보호를 우선하는 즉시 권장안이다.
B 새 제작은 일반 전용, 기존 활성 장비는 레거시 유지: 장기적으로 일반 베이스의 역할이 명확해진다. 다만 판정 함수에 rarity==0 한 줄만 추가해서는 안 된다.
C 기존 매직 룬워드 전부 해제/너프: 사용자 자산을 소급 약화한다. 비권장.

B를 추후 선택할 때 필요한 이관:
- 판정·삽입·소켓 작업·상점/툴팁/레시피 안내를 같은 규칙 버전으로 바꾼다.
- 기존 활성 비일반 룬워드는 전용 legacy 허용 기록을 붙여 효과 유지. 아직 완성하지 않은 고급 베이스/삽입 중인 룬의 처리도 별도 결정한다. 계정 창고/거래/장착/가방 전체를 포함한다.
- 아이템 문자열을 확장하면 뒤 필드 기본값·구버전 읽기·거래 저장까지 왕복 검사. 클라이언트가 임의 legacy 표식을 요청할 수 없게 서버가 이관한다.
- 기존 효과가 사라지는 실패 케이스를 우선 검사하고, 변환 전 원본을 보존한다. 오프라인 계정 전수 이관을 수행했다고 주장하지 않는다.
승인 기준: 모든 기존 활성 장비의 적용 옵션이 전후 동일, 새 제작에서 등급별 허용/거절과 비용/룬 보존이 일관됨. 색상만 보고 상위라고 오인하지 않게 일반·매직 기회비용을 설명한다.

4. I03 — 소환 변종 편성 및 축소·통합

현재: UndeadSystem.ApplySkeletonForm은 방패→대검→쌍칼, ApplyMageForm은 광기→저주→쌍발→관통→폭발 순. 각 노드 랭크가 정원이면서 해당 효과 세기도 올린다. 최대 수를 초과한 앞 변종 때문에 뒤 변종은 배워도 0기가 될 수 있다. 오라/저주 같은 효과의 최댓값 규칙을 개체 수만큼 합산하면 안 된다. 소환 순간 스냅샷을 기존 개체에 즉시 소급하는 것도 현행과 다르다.

단계1 권장 최소안(새 편성창 없이):
- 스킬 상세/기존 군단 창에 '배운 정원 / 현재 일반형·변종 수 / 다음 소환 예정 변종'을 구분해 표시.
- 다음 랭크를 찍어도 해당 변종을 배치할 수 없으면 '현재 우선순위에서 0기, 편성 변경 또는 상한 필요'를 미리 보인다. 랭크 세기 증가와 개체 추가가 다르다는 안내를 준다.
- 기존 우선순위와 저장은 유지한다. UI를 위해 실제 MakeRecord/소환/TrimOldest를 실행하지 않는다.

단계2 권장 편성안:
- 기존 군단 창의 '자동/직접' 선택. 자동은 현행과 같은 초기값.
- 직접은 변종별 희망 수를 0~학습 정원으로 지정하고 합은 현재 MaxFor 이내. 비운 자리는 일반형. 전사/마법사 각각 저장한다.
- 편성 변경은 다음 소환부터 적용. 이미 살아 있는 개체를 자동 처형/무료 재생성하지 않는다. 낮아진 상한/리셋 시 불가능 정원은 표시만 경고하고 다음 소환에서 합법 수로 제한한다.
- 일으키기 전에 현재 살아 있는 변종+거인 예약 수를 포함해 다음 자리를 정한다. 교체될 가장 오래된 개체까지 고려해야 예고가 실제와 일치한다.
- 랭크업은 효과 세기와 학습 정원을 유지하되 UI에서 둘을 분리한다. 사용자 지정 수를 장비 교체 때 덮어쓰지 않는다.

축소/통합 대안:
A 5종 유지+편성 개선: 역할/기존 투자 보존이 좋다. 관리 부담이 커질 수 있어 자동을 기본으로 둔다. 우선 권장.
B 광기+저주를 지원 역할 한 개로, 쌍발/관통/폭발을 공격 방식 선택으로 묶기: 관리 개념을 줄인다. 하지만 광기와 저주는 아군 버프/적 디버프로 다르므로 단순 합산은 과강해지고 두 개를 뺏으면 기존 빌드가 사라진다. 실측 뒤 후보.

5. I04 — 모바일 기본공격, 다섯 칸, 입력 피로, 무효 투자 안내

대안: 모든 사람에게 6버튼 강제는 화면 과밀. 제스처만으로 기본공격 숨기기는 발견성/오발 위험. 먼저 고급 배치의 분리 단추와 취소를 실기 검증한다.

이번 작은 구현: SkillBook.UseHint를 노드 상세·추천에 연결했다. 모인 뼈의 골편1발, 잔걸음의 질주 미습득, 뼈 껍질의 갑옷 미습득을 안내한다. 선투자·구매 전제·기존 포인트는 바꾸지 않았다. F07에서 노드 장비 보너스 오류도 함께 막았다. 노드 선택을 두 번 눌러도 설명만 보며, 배우기/강화 버튼으로 투자한다.

6. I05 — 실제 빌드 기반 계산과 실전 계측

현재 tools/sim.py fight는 playerBaseDps 등 가정값과 단순 그림자 전투다. 실제 장비/스킬/변종/시전 입력/다중 적중을 재현하지 않으므로 실제 빌드 DPS 순위 근거로 쓰지 않는다. 이번 Lua 회귀검증은 실제 함수·일반형 소환 기록을 실행하지만 MSW의 투사체/AI/피격 판정 시뮬레이터는 아니다.

계산기 입력 계약(제안):
버전SHA, 캐릭터레벨/난이도/능력치/투자Levels, 장비 원문 문자열과 세트·룬·선택보상, 슬롯/입력 패턴, 대상 sourceId·레벨·등급·저항·방어·보호 상태, 실제 소환 기록(종·변종·원소·랭크·스냅샷·공격간격), 조건(저주/서리/오라/자원/일시 버프).
장비 스킬 상한/사용 가능 노드는 PlayerStats/SkillBook의 현재 함수를 그대로 쓴다. 별도 표의 계수 복사로 맞추지 않는다. 현재/다음/장비 전후 평가를 동일 입력 스냅샷으로 만든다. 미습득과 rank1 가정, 기초와 실제를 구분한다.

출력 3층:
1) 설명 가능한 한 타격/한 시전: GetEffectPower·실제 피해 판정의 단계별 값, 유효 랭크, 마나, 일반 재사용 또는 질주 충전. 대상 저항·레벨차·Guard·저주·흡수 전/후를 나란히.
2) 가정 기반 상한: 한 타격 피해×유효 적중 수×가능한 발동 빈도. 실제 적중수/가동률을 모르면 범위 또는 미계산으로 둔다. 쿨다운뿐 아니라 애니메이션/입력 점유/마나·회복·대상 접근 시간을 포함. 독은 최강값 덮어쓰기, 오라·동일 저주는 최댓값, 관통은 적별 피해, 여러 발을 한 적에 전부 곱하지 않는다.
3) 계측된 실효치: 고정 시나리오에서 실제 HP가 줄어든 양/전체 구간. 전투 중 수치와 준비·군단 복구를 포함한 전체 구간을 둘 다 제공한다. 계산값을 실측이라고 쓰지 않는다.

작은 구현 경로(아직 미구현):
- 기존 Telemetry/게임 이벤트 체계를 확장하는 개발용 계측을 먼저 한다. 새 외부 분석 서비스를 전제로 하지 않는다.
- 피해 확정 지점: Monster.HandleHitEvent의 RiteAbsorb 뒤, Monster.TakeDamage의 실제 HP 감소 뒤. PlayerAttack/ShadowUnit CalcDamage에만 합산하면 빗나감/흡수/독/반사를 놓치고 중복할 수 있다.
- 이벤트 키는 세션/대상 생성번호/HP 적용 순번. owner·source(기본공격/기술/소환/독/반사), 적용전HP·적용후HP·흡수·과잉피해·시각을 한 번만 기록. 표시용 QueueSummonDamage/틱 합산 숫자는 측정 원장이 아니다.
- effectiveDamage=min(max(0,HP_before), max(0,HP_before-HP_after)); overkill과 흡수를 따로 센다. 대상 리셋·회복·재생성은 별도 사건으로 기록한다.
- DPS=effectiveDamage/구간초. 준비/회피/자원 고갈 포함 총DPS, 실제 공격 가능한 구간DPS, 처치시간, 피격/사망, 입력/분, 마나·혼 소모, 소환 복구시간, p95 서버틱/기기 프레임을 함께 본다.
- 저주는 직접 피해와 기여를 분리. 같은 빌드에서 저주 사용/미사용의 짝지은 실험으로 추가 피해·피해 방지·회복을 보고한다. 총 피해와 추가 기여를 더해 중복 총DPS로 만들지 않는다.
- 서버 메모리에 합산, 개발자 허용 시험만 캡처. 매타격 DataStorage 쓰기/전역 순위/무제한 로그를 추가하지 않는다. 기존 5분 flush·저장크기·보존기한/비용 정책을 확인하고 상한 있는 요약만 저장한다.

시험표:
소환/마법/저주혼합 × 편안한 조작/숙련 조작 × PC/모바일.
동일 레벨·실투자 총점·장비 예산, 보스1기(이동/보호 포함), 넓은 무리, 협로, 원거리 이동 적, 60초 자원 지속, 군단 전멸 후 복구. 각 반복 수/실패/장비/빌드/입력/seed·비결정 조건을 남긴다. 임의 승자나 목표DPS 배수를 먼저 정하지 않는다.
승인 기준: 고정 HP 대상에서 합산 피해와 실제 HP 변화(회복·흡수 보정)가 맞고, 주문/소환/독/반사/과잉피해가 한 번씩만 귀속됨. 정적 계산과 계측 차이를 설명할 수 있어야 한다.

7. I06 — 납골당→사원→등대→성채의 다른 반복 진행

공통 범위: 66개 전면 재제작을 시작하지 않는다. 대표 맵 1개씩만, 기존 모델/적/기능으로 먼저 시험한다. remix는 미술 재질과 소품까지 같다는 뜻은 아니나 공간 골격을 반사하는 방식이 남아 있다. 실제 지루함은 플레이 가설이다.
현재 동선 설명은 데이터/형상에 따른 정적 요약이며 모든 곁방을 반드시 청소해야 한다는 런타임 결론이 아니다. 주 경로 보상과 선택 경로 보상을 구별한다.

A 납골당 crypt2 (act1)
현재: crypt1 진입→여러 방/중앙 연결부를 거쳐 crypt2→crypt3 근위대장→queentomb 여왕→NPC 보고/유니크. 첫 장비는 이보다 이른 hollow 의뢰가 이미 제공한다.
제안: crypt2 입구에서 다음 출구가 읽힘→짧은 주 경로 전투→한 선택 시험방(방패/원거리의 좁은 공간 또는 무리/둥지의 넓은 공간)→합류→crypt3. 두 시험방 모두를 돌 필요는 없다.
없앨 것: 같은 목적 없이 나머지 곁방을 되짚는 길과 중복 설명. hollow의 첫 장비/포인트를 여기까지 늦추지 않는다.
새 판단: 내 주력 방식으로 좁은 방/넓은 방 중 무엇을 시험할지. 기존 해골/골편/저주·그림자 차이를 확인.
재사용: 수비병/석궁병/무리·둥지, 상자, 기존 출입구/랜드마크.
보상: 필수 포인트·군단 기반은 현재 주 진행에서 유지. 선택방은 기존 추가 장비/룬/자원 기회. 두 방에 영구 포인트를 나눠 사실상 모두 돌게 하지 않는다. 최종 군단/모든 변종/완성 룬워드는 남긴다.
제작 최소: crypt2 spec의 방/길·스폰 배치만 바꾸는 첫 시안. 신규 시스템/에셋0으로 검증 가능.
실패: 두 방 완주가 정답 강제, 기본 빌드만 통과, 기존 총 적/보고 횟수 증가, 출구/벽 가독성 악화.

B 사원 temple2 (act2)
현재: temple1→temple2(crypt3 골격 remix), 두 문지기 처치(count2)→temple3→sanctum→보고/유니크. 현행 한 문지기 사망 후 다른 쪽 분노는 이미 있다.
제안: 긴 기둥 회랑+짧은 측면 통로 중 하나 선택→같은 문지기 구역 합류→어느 문지기를 먼저 상대할지 판단→다음 층. 두 경로의 적 일부를 바꿔 시야·우선처치 순서가 다르게 한다.
없앨 것: 중앙방-곁방을 같은 순서로 훑는 대표 골격의 반복. 새 퍼즐 열쇠/추가 문지기 보스는 만들지 않는다.
새 판단: 엄폐/접근 방식과 쌍둥이 대응 순서. 어느 계열도 필수 면역 검문소로 만들지 않는다.
보상: 기존 문지기 후 룬, 액트 보스 고유 보상 유지. 선택 측면로는 드러난 약점을 보완할 후보/자원. 양갈래를 모두 돌려 모으는 필수 조각으로 묶지 않는다.
제작 최소: temple2 spec 1개, 기존 기둥/근접·원거리 적 위치. 기둥의 시야 차단 기능은 현재 물리에서 확인해야 하며 그림만으로 엄폐된다고 전제하지 않는다.

10. 검증 한계
