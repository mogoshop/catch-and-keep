# 직업 & 스킬

## 1. 직업 구성 전략

D2는 7개 직업이 각각 3개 스킬 트리(총 30스킬)를 가진다. 인력이 부족하므로 **네크로맨서 1개를 끝까지 만들고**, 나머지 원형은 골격만 정의해 둔다. 직업 하나는 스킬 27~30개, 이펙트 30개, 애니메이션 세트가 필요하므로 추가 비용이 크다.

| 단계 | 직업 | 시점 |
| --- | --- | --- |
| P0~P1 | 네크로맨서 | 최우선. 코어 루프의 중심 |
| P2 | 후보 1개 추가 (4장 4절 중 택일) | 네크로맨서 완성 후 |
| P3 | 나머지 | 선택 |

## 2. 스킬 시스템 규칙

| 규칙 | 내용 |
| --- | --- |
| 구조 | 직업당 3트리, 트리당 9~10스킬 |
| 습득 | 스킬 포인트 1로 레벨 +1. 최대 레벨 20 (기본) |
| 요구 레벨 | 트리 내 행(row)별 1, 6, 12, 18, 24, 30, 36, 42, 50 |
| 선행 스킬 | 직전 행 스킬 1개 이상에 1레벨 이상 투자 |
| 추가 레벨 | 장비 "그림자 스킬 레벨 +N" (룬워드 전용, 합산 최대 +3) |
| 시너지 | 관련 스킬 레벨 1당 대상 스킬의 피해·효과 +N% (D2 방식) |
| 유형 | **액티브** (키 발동) / **패시브** (상시) / **오라** (지속, 마나 점유 없음) / **저주** (대상 지정) |
| 키 배치 | 액티브 스킬 슬롯 8개 (08장) |
| 초기화 | 후반 재료 소모로 가능 (P2) |

포인트 예산: 레벨 80까지 79 + 퀘스트 6 = **85포인트**. 27스킬을 전부 올릴 수 없으므로 빌드 선택이 생긴다. (D2도 같은 철학)

## 3. 네크로맨서 스킬 트리 (27종)

이름은 모두 오리지널. D2 대응은 "무엇을 벤치마킹했는가"를 명시한 참고용이며 이름·효과를 복제하지 않는다.

## 4. 후속 직업 원형 (골격)

D2 7직업을 우리 형태로 옮긴 후보. 확정은 네크로맨서 완성 이후.

| 후보 | D2 원형 | 컨셉 | 트리 3개(가칭) | 대표 스킬 | 2D 적합성 |
| --- | --- | --- | --- | --- | --- |
| 격투가 | 야만전사 | 근접 광전사 | 전투 기술 / 포효 / 숙련 | 도약 강타, 회전 베기 | 높음 |
| 궁수 | 아마존 | 원거리 궁수 | 활 / 투창 / 보조 | 연속 사격, 낙하 화살 | 높음 |
| 마도사 | 소서리스 | 원소 마법 | 화염 / 냉기 / 번개 | 화염구, 빙결 폭발 | 높음 |
| 성전사 | 팔라딘 | 오라와 방어 | 전투 / 오라 / 신성 | 방패 돌진, 수호 오라 | 중간 |
| 정령사 | 드루이드 | 변신과 자연 | 원소 / 변신 / 소환 | 늑대 변신, 불의 화산 | 낮음 (변신 애니메이션) |
| 암살자 | 어새신 | 함정과 격투 | 격투 / 함정 / 그림자 | 그림자 분신, 함정 설치 | 중간 |

추천: **격투가** 또는 **마도사**. 애니메이션·이펙트 재사용이 쉽고 파티 상호작용(네크로맨서의 저주와 시너지)이 선명하다. 이 선택은 12장 결정 필요 목록.

## 6. 스킬 데이터 구조 (구현 참고)

```lua
SkillData = {
  shadow_summon = {
    tree = "command", row = 1, type = "active", reqLv = 1, prereq = nil,
    maxLv = 20, cooldown = 0, mpCost = { base = 5, perLv = 0.5 },
    synergy = nil,
    scale = { ... },  -- 레벨별 수치 테이블, 10장에서 CSV로 관리
  },
}
```

스킬 효과의 서버 구현은 스킬 한 종류당 한 스크립트로 두지 않고, 공통 **효과 타입**(투사체, 범위 지대, 버프, 소환 등) 6~8종 조합으로 데이터 주도 구현한다. 27개 스킬을 27개 스크립트로 쓰면 유지가 어렵다.
