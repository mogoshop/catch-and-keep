사용자 (10-29): 「인벤토리나 창고, NPC, 그림자 창 등 전반적인 UI에 대해서도 평가해 줘. 보완해야 한다면 동일하게 보완점까지.」 스킬 창은 「완성됐고 마음에 든다」 — **기준점(5점)**으로만 쓰고 평가하지 않는다.

### 0-2. 진단 다섯 줄

1. **스킬 창(35점)과 나머지의 격차는 「몸통」이 아니라 「규격·반응」이다.** 28개(대장간 포함) 평균 21.9점. 창 틀이 두 갈래(kit.frame 14개 · 별도 빌더 7개 — 제목 28 #E6C88A·외곽선 없음·닫기 위치 다름·`ui-tokens` 미사용)이고, 탭이 7가지 모양(높이 52~88), 바탕이 4가지(어두운 a1 · 비치는 a0.94 · gauge_fill · 남색)다(§2-1).
2. **누르면 아무 소리도 안 난다.** 창 컨트롤러에서 소리를 내는 곳은 NPC 대화 열기·제물 카드·음량 적용 세 곳뿐. 구매·판매·장착·입출고·소켓·이동·탭·닫기 모두 무음이고, 마우스를 올렸을 때 반응은 엔진 기본 틴트(0.96/0.78)뿐이다(§2-4).
3. **레벨업 띠가 창을 덮는 원인을 찾았다.** 띠는 RewardHUD(그룹 16)의 Toast라 Story·Confirm 말고 모든 창 위에 그려지고, `UXFeedback.Tick`은 창이 열렸는지 보지 않는다(UX:68-107). 모바일은 Toast를 화면 위 가운데(ML:45)로 옮겨 **소지품 창 한가운데**에 떨어진다 — PC·모바일 둘 다 재현(`pc-26c` · `m-26c`). 같은 Toast를 34곳이 부른다.
4. **모바일(iPad)에서 넓은 창 5개가 잘린다** — 그림자 보관함 1560(양쪽 단추 잘림, `m-09`) · 혼의 제물 1400 · 소지품 1400 · 상점 1380 · 안내 1560. 88 미만 단추가 모바일에 보이는 곳이 18개 창 120여 개(그림자 17 · 플레이어 34 · 거래 48 …)이고, 웨이포인트·거래가 열린 동안 모바일 패드가 숨지 않아 창 위에 겹친다(`m-07`).
5. **개발 메모·버그성 동작이 플레이어 화면에 보인다** — 미리보기 「(승인 전)」·「그림 자리」(`pc-24`), 채널 「메이커 테스트는 채널 하나」, 플레이어 창 「없습니니/다」 줄바꿈(`m-14`), 확인 창에서 Esc → **뒤의 소지품 창까지 닫힘**(`pc-21b`), 거래 창이 창 목록에 없어 Esc·전투 입력 차단이 안 됨, 로비 Esc → 게임 고르기 창이 다시 안 열림.

## 1. 창별 평가

각 창: 캡처 2장(PC · 모바일) → 7항목 → 문제 → 보완 복수안(안 | 내용 | 예상 | 위험 | 구현량 | 바뀌는 파일). 단축키·조작 수는 코드를 따라 센 값이고 메이커에서 실제로 연 경로로 확인했다.

### 1-0. 기준: 스킬 창 — 왜 좋은가 (평가 제외 · `pc-00-skill-baseline` · `m-00-skill-baseline`)

- **한 화면 두 판** — 위 「해금 시간선」(`sk_timeline_panel` 1298×356) · 아래 「스킬 공방」(`sk_workshop_panel` 1298×452), 탭이 없다. 트리 구분은 테두리 색 + 머리 줄 범례 「■ 소환 ■ 영혼 ■ 저주 ■ 이동」(SkillWindow.mlua:59-72).
- **상태별 그림 세트** — 칸 테두리 4상태 × 2크기(`sk_tl_node_{frame,selected,locked,learnable}_{64,96}`), 노드 4상태, 연결선 2상태, 랭크 점 3상태. 상태를 색이 아니라 **그림**으로 바꾼다.
- **여백 토큰** — 판 안 여백 `SKPANEL.pad`(tok:28)를 빌더와 실행 중 배치가 같이 쓴다.
