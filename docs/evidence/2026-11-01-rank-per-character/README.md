# 랭킹 「캐릭터 단위」 전환 (11-01 사용자 결정 1-B)

증상: Lv40 노말 캐릭터 「새내기」로 랭킹(L)을 열어도 같은 계정 「인꾸」의 Lv60 지옥 기록이 「내 순위 1위」로 나왔다.
원인: `RankingSystem`이 모든 판을 계정 키(`PlayerComponent.ProfileCode`)로 적고 읽었다. 이름 저장소(`rank_names`)에도 계정 키로 **계정 닉네임**(`pc.Nickname`)을 적었다.
결정: 계정 단위가 아니라 캐릭터 단위. 한 계정의 여러 캐릭터가 상위 10에 여러 줄을 차지할 수 있다(사용자 수용).

구현 레인은 메이커를 쓰지 않았다(다른 담당 점유). 오프라인 확인은 아래 「검사」. 메이커 확인은 맨 아래 절차.

## 1. 키 체계

| 항목 | 11-01 전 (그대로 남김) | 지금 |
|---|---|---|
| 기록 키 | `ProfileCode` | `ProfileCode_c<슬롯>_<만든 시각 ms>` 예: `…_c4_63928683821328` |
| 판 이름 | `rank_<kind>_<diff>` | `rank_<kind>_<diff>_c1` (`BoardSuffix`) |
| 이름 저장소 | `rank_names` (계정 키 → 계정 닉네임) | `rank_names_c1` (캐릭터 키 → 캐릭터 이름) |
| 표시 이름 | 계정 닉네임 | `PlayerSave.CharName()` = 이름표의 캐릭터 이름 (후원·업적 칭호 줄 제외, `| ;` 제거) |

- 판 이름이 달라서 계정 줄과 캐릭터 줄이 한 판에 섞이지 않는다. 예전 판·이름은 **읽지도 지우지도 않는다**. 되돌리려면 이 커밋을 되돌리면 예전 판이 그대로 다시 보인다.
- 「내 순위」, 연타 방지(같은 판 5초), `Known`·`MineAt`·`MineRecorded`·`NameWritten` 캐시는 모두 캐릭터 키 기준. 캐시 구조와 `[VRF] rank mine board=… rank=… value=…` 형식은 그대로다(판 이름에만 `_c1`).
- 캐릭터를 아직 고르지 않았으면(슬롯 0) 기록하지 않고 `[VRF] rank record skip … reason=nochar`를 남긴다. 그때 「내 순위」는 「기록 없음」이다.

### 캐릭터 id를 `created`로 만든 근거 (저장 형식 변경 없음)

- `PlayerSave` 슬롯 요약 `Account.slots[N]`에는 이미 `created = DateTime.UtcNow.Elapsed`(ms 정수)가 있다. 새 캐릭터(`RequestCreateSlot`)와 예전 저장 옮기기(`Load` legacy) 두 경로 모두 적고, 만든 뒤에는 바꾸는 코드가 없다(`Collect`는 lv·diff만 고친다).
- 슬롯을 지우고 같은 칸에 새로 만들면 새 시각이 되므로 새 id가 된다. 따라서 옛 기록이 넘어가지 않는다. 슬롯 번호도 id에 넣어 같은 계정 안에서 겹치지 않는다. ProfileCode를 앞에 붙여 다른 계정과도 겹치지 않는다.
- JSON 정수로 저장된다. 14자리 값은 2^53보다 작다. 메이커 실제 저장에서 `"created":63927142517160`(1번 「인꾸」, 예전 저장에서 옮긴 캐릭터) 등 4칸 값이 10-29 백업(`docs/evidence/2026-10-29-*/slot4-*.json`)과 11-01(`docs/evidence/2026-11-01-bugfix-three/maker/slot4-after-entry.json`) 사이 여러 번 다시 저장된 뒤에도 같았다. 실수로 읽혀도 `math.floor` 뒤 `%d`로 같은 글자가 된다(검사 `rank_per_character` §1).
- 그래서 **저장 형식은 바꾸지 않았다.** 옛 세이브는 그대로 읽힌다. `created`가 없는 슬롯은 실제로는 없지만, 있다면 그 캐릭터는 기록되지 않고 skip 로그만 남는다.

## 2. 옛 기록 처리: 옮기지 않음

| 판 | 플레이어에게 보이는 결과 |
|---|---|
| 성장 순위 | 게임 방에 들어갈 때(`FinishLoad` → `RecordProgressLater`)와 레벨업·의뢰 완료 때 캐릭터마다 새로 적혀 채워진다. 아직 안 들어온 캐릭터만 비어 있다. 「내 순위」를 먼저 열면 이번 답은 「기록 없음」이고 그때 한 번 적으므로, 다시 열면 보인다. |
| 보스 처치 시간 | 새 판에서 처음부터 시작한다. 업데이트 뒤 마지막 액트 보스를 처음 잡기 전까지 목록은 「아직 기록이 없습니다」, 「내 순위」는 「기록 없음」이다. |
| 심연·이번 주 | 새로 시작한다. 심연은 10-24부터 숨김(`depthEnabled 0`) 상태라 탭도 보이지 않는다. 이번 주 판은 원래 주마다 새로 시작한다. |

이름 일치로 한 번 옮기는 방법을 쓰지 않은 이유:

1. **이름이 캐릭터를 가리키지 않는다.** 옛 `rank_names`의 값은 기록을 세운 캐릭터 이름이 아니라 계정 닉네임(`pc.Nickname`)이다. 닉네임과 같은 이름의 캐릭터는 보통 1번 기본 이름이다. 그래서 「이름 일치」로 옮기면 계정의 옛 기록이 전부 그 캐릭터에게 간다. 메이커 예: 계정 「인꾸」의 옛 성장 줄 「인꾸 Lv60 지옥」은 지금 어느 캐릭터 상태(인꾸 Lv17, 인꾸 2 Lv16, 핏빛망령 Lv4, 새내기 Lv40)와도 맞지 않는다. 고치려는 잘못(다른 캐릭터 기록이 내 것으로 보임)이 그대로 다시 생긴다.
2. **비용과 「한 번만」 보장.** 계정마다 옛 이름 1번, 보스 3판, 심연 도전 12판(+최고 층 12판, 이번 주 12판)을 GetAndWait로 읽어야 한다. 정렬 저장소의 묶음 조회는 판 하나 안에서만 된다. 여기에 쓰기와 「누가 가져갔나」 표시 저장소까지 붙으면 계정당 10~40 크레딧이 든다. 업데이트 직후 여러 명이 동시에 들어오면 PlayerSave와 같은 Get/Set 크레딧 묶음(분당 100 + 접속자×10)을 한꺼번에 쓰게 된다. 한 계정에 같은 이름 캐릭터가 둘이면(`CleanName`은 중복을 막지 않는다) 따로 표시 저장소를 써야 한 번만 옮긴다는 것이 보장된다.
3. **얻는 것이 작다.** 실제로 옮길 의미가 있는 판은 보스 3판뿐이다. 메이커와 배포판은 저장소가 따로라, 메이커의 옛 기록은 시험 값이다.

옛 판은 그대로 남아 있으므로, 나중에 원하면 「자기 캐릭터 데이터로 확인되는 기록만」(예: 그 난이도 보스 처치 흔적이 있는 캐릭터) 옮기는 별도 작업을 할 수 있다.

## 3. 캐릭터 삭제: 줄을 감춤 (지우지 않음)

- `PlayerSave.RequestDeleteSlot`은 계정 저장에 **성공했을 때만** `RankingSystem:HideCharacter(ProfileCode, slot, info)`를 부른다. 이 함수는 그 캐릭터 키의 이름 자리에 `HiddenName`(`|hidden`)을 적는다. 이름에는 `|`가 들어갈 수 없으므로 진짜 이름과 겹치지 않는다. 저장에 실패하면 다음 접속에 슬롯이 돌아오므로 감추지 않는다.
- `GetTop`은 이름이 `|hidden`인 줄을 건너뛴다. 처음 10줄에 섞이면 이름을 25줄까지 한 번 더 읽어 10줄을 채운다. 평소처럼 섞이지 않으면 이름 조회는 1번으로 예전과 같다. 「내 순위」는 자기 위에 있는 감춘 줄 수를 빼서 셈한다(`hiddenAbove`). 같은 서버의 60초 캐시는 비운다.
- 기록 줄을 지우지 않은 근거:
  - PlayerSave 삭제도 저장 데이터를 남기는 방식이라 같은 성격으로 맞췄다. 이름만 되돌리면 줄이 다시 보인다.
  - 판마다 지우면 진행·보스 3·심연 12·최고 층 12·이번 주 12, 최대 40번의 Delete 요청이 든다(Delete 묶음은 분당 50 + 접속자×2). 감춤은 Set 1번이다.
  - 같은 칸의 새 캐릭터는 새 id라서 옛 줄과 섞이지 않는다.
- 한계:
  - 다른 서버 인스턴스는 60초 캐시가 끝나야 감춰진다.
  - 내 순위 셈은 이름을 읽은 줄(상위 25)에서만 감춘 줄을 뺀다. 26~100위 사이에 지운 캐릭터 줄이 있으면 그보다 아래인 사람의 순위가 그 수만큼 크게 보일 수 있다. 드문 경우라 비용을 늘리지 않았다.

## 4. [VRF] 로그 (서버)

| 줄 | 언제 |
|---|---|
| `[VRF] rank record board=<판_c1> char=c<슬롯>_<ms> name=<캐릭터 이름> value=<값> prev=<이전 값 또는 nil>` | 기록이 좋아져 적을 때 (prev=nil이면 새 판 첫 기록) |
| `[VRF] rank record skip board=<판> reason=nochar` | 캐릭터를 안 고른 상태에서 기록 요청 |
| `[VRF] rank top board=<판> rows=<첫 쪽 줄 수> shown=<보낸 줄> hidden=<건너뛴 감춘 줄> names=<이름 읽은 줄>` | 상위 목록을 새로 읽을 때 (60초 캐시 안이면 없음) |
| `[VRF] rank char board=<판> char=<id> name=<이름> hiddenAbove=<n>` | 「내 순위」 계산 (바로 다음 줄이 기존 `rank mine`) · 캐릭터 없음이면 `char=none` |
| `[VRF] rank mine board=<판> rank=<순위> value=<값>` | 기존 형식 그대로 |
| `[VRF] rank hide char=<id>` | 캐릭터 삭제로 줄 감춤 |

로그에는 계정 ProfileCode를 남기지 않고 캐릭터 id만 남긴다.

## 6. 메이커 확인 절차 (실제 플레이어 여정 · 저장소 초기화 없음)

메이커 담당 한 명이 한다. 함수 직접 호출(`maker_execute_script`로 Record·MineDigest 부르기)로 대신하지 않는다. `maker_reset_data_storage`·`maker_save`는 쓰지 않는다.

**준비**
1. 플레이를 멈춘다. `.mlua` 2개(`Endgame/RankingSystem`, `Player/PlayerSave`)만 바뀌었고 UI·동기화 속성 추가는 없다.
2. touch → `refresh` 1번 → `logs(kind="build")`에서 오류 0을 확인한다.
3. `clear_logs` → 플레이.
4. 메이커 계정 슬롯은 11-01 기준 1 「인꾸」 Lv17 · 2 「인꾸 2」 Lv16 · 3 「핏빛망령」 Lv4 · 4 「새내기」 Lv40이다. 아래 id는 이 `created` 값에서 나온다. 슬롯이 바뀌었으면 선택 창 Account JSON의 created로 다시 계산한다.

| 슬롯 | 이름 | 캐릭터 id |
|---|---|---|
| 1 | 인꾸 | `c1_63927142517160` |
| 2 | 인꾸 2 | `c2_63927144766051` |
| 4 | 새내기 | `c4_63928683821328` |

**A. 4번 「새내기」**
1. 캐릭터 선택에서 4 「새내기」를 고른다 → 로비 방 창에서 게임 방에 들어간다 → 1초 이상 기다린다.
   - 기대 로그: `[VRF] rank record board=rank_progress_0_c1 char=c4_63928683821328 name=새내기 value=40xx prev=nil`. 새 판 첫 입장이면 prev=nil이고, 값 = 4000 + 난이도×10 + 액트다.
2. L로 랭킹 창(성장 순위 탭)을 연다.
   - 목록에 「새내기 Lv40 · …」 줄이 있다.
   - 아래 금빛 줄은 「내 순위  N위 · Lv40 · 노말 액트 X」다. **Lv60 지옥이 아니어야 한다.**
   - 로그: `[VRF] rank top board=rank_progress_0_c1 rows=… shown=… hidden=0 names=…`, `[VRF] rank char board=rank_progress_0_c1 char=c4_63928683821328 name=새내기 hiddenAbove=0`, `[VRF] rank mine board=rank_progress_0_c1 rank=N value=40xx`.
3. 「보스 처치 시간」 탭을 연다.
   - 목록은 「아직 기록이 없습니다」(업데이트 뒤 아무도 안 잡았으면), 「내 순위  기록 없음」이다.
   - 로그: `[VRF] rank mine board=rank_boss_ash_king_<난이도>_c1 rank=0 value=0`. 옛 계정 기록은 이어받지 않는다.
4. 성장 탭과 보스 탭을 5초 안에 빠르게 여러 번 누른다.
   - 같은 판에 대해 `[VRF] rank mine` 줄이 늘지 않는다(연타 방지).

**B. 같은 계정 1번 「인꾸」**
1. 메뉴 「캐릭터 선택으로」 → 1 「인꾸」 → 게임 방에 들어간다 → 1초 기다린다.
   - 로그: `[VRF] rank record board=rank_progress_0_c1 char=c1_63927142517160 name=인꾸 value=17xx prev=nil`.
2. L → 성장 순위 탭.
   - 목록에 같은 계정의 「새내기 Lv40」 줄과 「인꾸 Lv17」 줄이 **따로** 있다.
   - 「내 순위」는 인꾸의 순위와 「Lv17 · …」다.
   - 로그: `[VRF] rank char … char=c1_63927142517160 name=인꾸 …`.
3. 보스 탭: 「내 순위  기록 없음」이다(새내기 기록도 옛 계정 기록도 이어받지 않음).
4. (선택) 2 「인꾸 2」로 같은 확인을 한다. 이름이 닉네임과 비슷해도 `char=c2_63927144766051 name=인꾸 2`로 따로 적혀야 한다.

**판정**
- 위 `[VRF]` 줄이 모두 나오고, 「내 순위」가 지금 캐릭터 값이고, 빌드 오류가 0이면 PASS다.

**메이커에서 확인하지 않는 것**
- 캐릭터 삭제 경로: 메이커 슬롯 4칸이 다 차 있어 새 캐릭터를 만들려면 기존 캐릭터를 지워야 한다. 사용자 데이터라 지우지 않고, 오프라인 `rank_per_character` §6으로 대신한다.
- 슬롯 4는 다른 검증(S48 복원)의 기준이다. A는 입장과 랭킹 창만 보고 전투·장비 변경은 하지 않는다. 걱정되면 A를 2 「인꾸 2」로 대신한다.

## 7. 남은 위험 · 다른 담당에게

- `RankWindow.mlua`(다른 담당 소유)는 **바꿀 필요가 없다.** 다이제스트(`이름|값;…`)와 내 순위(`순위|값`/`none`) 형식이 그대로다.
  - 선택 개선안: 「내 순위」 줄에 지금 캐릭터 이름을 붙이고 싶으면 `MineText`의 반환을 `"내 순위 (" .. 캐릭터이름 .. ")  " .. …`로 바꾼다. 이름은 클라이언트에서 `_UIKit:Comp("script.PlayerSave"):CharName()`으로 얻는다. 지금은 넣지 않았다.
- 기존 잠재 문제(이번 범위 밖, 심연을 다시 켤 때 확인 필요): `ReadSorted`가 `GetSortedAndWait(dir, 1, 999999)`로 읽는다. 그런데 심연 도전 값은 `층 × 100000 + …`라 10층부터 999999를 넘는다. 그런 기록은 정렬 목록과 「내 순위」 첫 쪽에서 빠진다.
