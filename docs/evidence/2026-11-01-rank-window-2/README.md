## 1. UI 판단과 근거

### 공백의 원인
예전 창(640 × 660)은 탭 줄(−86 ~ −142) 아래에 **심연 탭에서만 쓰는 액트 넘김 막대 자리(−166, 높이 76)** 를 늘 비워 두고 기록 칸을 −218에 두었다 → 성장·보스 탭(심연을 숨긴 지금 배포 상태 그대로)에서 탭 아래 76px 빈 띠.

### 바꾼 배치 (ui-tokens `RANK` = `RankWindow.Layout`)
- 탭 → **기록 판(탭 바로 아래 12)** → [머리 줄 → 목록 → 내 순위 줄]. 보이는 것만 쌓는다.
- 액트 넘김 막대는 따로 띠를 두지 않고 **기록 판 머리 줄 오른쪽**에 둔다. 심연 탭에서만 머리 줄이 막대 높이(76)가 되고 왼쪽엔 판 제목(이번 주 탭은 규칙 제목 + 규칙 두 줄, 세 줄).
- **창 테두리 위 끝(496)을 고정**하고 아래로만 늘고 준다 — 탭을 바꿔도 탭이 손 밑에서 움직이지 않는다.
- 창 바탕 1188(이전 640) → **탭 넷도 한 줄**(4×202 + 3×16 = 856 ≤ 안쪽 1086). 예전 「둘씩 두 줄 + 막대·판을 내리고 창 752」 배치가 없어졌다.

### 20위 배치 — 칸 4 × 5 (권장안 「1~10 | 11~20 두 칸」 대신)
- 칸 = 순위 | 캐릭터 그림(44×56) | 이름(위) · 기록(아래). 1·2·3·4 / 5·6·7·8 … 순서, 순위 숫자 1 금 · 2 은 · 3 동.
- 두 칸 10줄안은 하단 메뉴 줄 위(위 여백 포함)에 넣으려면 줄 40 · 그림 36×40까지 줄여야 했다(본문 728). 4×5 칸은 본문 668로 더 낮고 그림이 1.4배 — 「캐릭터도 작게」가 보이는 크기로 남는다. 스크롤 없음(PC 휠 스크롤 미지원).
- 「이름을 내리던지」를 반영해 이름 아래 줄에 기록을 둔다(칸 폭 264로 넷이 한 줄).
- 내 칸(내 순위 자리의 이름·값이 같을 때만)은 노란 이름 + 노란 바탕. 아래 **내 순위 줄도 같은 규칙**: 「내 순위 | N위 · 100위 밖 · - | 지금 캐릭터 그림 | 이름 | 기록·기록 없음」.
- 창 아래 모서리 꽃불 장식(B7 iPad 캡처에서 예전 「내 순위」 첫 글자가 장식 위에 겹쳐 보였다)과 떨어지게 내 순위 줄 글은 양끝에서 24 띄움 → 바탕 가장자리에서 75 (`RANK.cornerClear` 64 검사).

## 2. 캐릭터 그림 — 그리는 방법과 옛 줄
- 외형 = `PlayerSave.Look()` "g-h-f-s-t"(캐릭터 만들기에서 정한 값 · 예전 캐릭터는 기본 "m-1-1"). 캐릭터 선택 카드·파티 모집 판과 **같은 함수** `CharSelectWindow.Dress`(외형 + 기본 로브)로 UI 아바타(`char-card.cjs avatarOf` = AvatarGUIRenderer + CostumeManager)에 입힌다.
- 다른 사람의 오프라인 캐릭터: 서버 `RankingSystem`이 새 저장소 **`rank_looks_c1`(캐릭터 키 → 외형)** 에 적고, 목록을 만들 때 보이는 줄의 외형을 읽어 다이제스트 `이름|값|외형`으로 보낸다.
- **이름 저장소 `rank_names_c1`은 형식 그대로(이름만)**: 처음엔 「이름|외형」을 같은 줄에 붙여 요청 수를 0으로 하려 했으나, 예전 코드(되돌림 · 업데이트 직후 아직 예전 코드로 도는 인스턴스)가 그 값을 읽으면 이름 자리에 「m-2-2-2-2」가 보인다(오프라인 재현: 예전 RankWindow + 새 형식 값 → `1.  m-2-2-2-2   67초`) → 따로 둔다.
- 옛 줄(2차 전 기록 · 외형 없음): 기본 모습을 **그림자 색**(0.13, 0.12, 0.16)으로 칠해 「아직 모르는 모습」으로 둔다 — 남의 캐릭터를 기본 남자로 잘못 보이지 않게. 빈칸보다 자연스럽고 게임 주제(그림자)와 맞는다.
- 옛 줄 채우기: ① 그 캐릭터의 기록이 좋아지면(레벨업 등) `Record`가 이름과 함께 외형을 쓴다 ② 목록에 보이는 옛 줄의 주인이 창을 열면 `FillLook`이 한 번 채우고, `PatchLook`이 그 답·60초 캐시의 내 줄에 바로 넣는다(처음 연 답부터 내 칸이 내 모습 · 저장소 요청 없음).

## 4. 같이 고친 것
- **정렬 조회 상한** `999999` → `SortMax` 2,000,000,000: 심연 도전·이번 주 값 = 층 × 100000 + …라 **10층부터 판에서 빠졌다**(미리보기 「전 · 심연 켬」에서 13·12·11·10층 줄이 없고 9층이 1위). 지금 심연은 숨김이라 실사용 영향 없음.
- **선택 보상 칸 꼬리표 간격**(관찰 1): 이름·단계 글을 꼬리표 끝에서 `PLATE.gap`(6) 띄움 — 꼬리표 x 6~58 · 글 x 64~173 (칸 179×52 · PC·iPad 같은 자리). `check_mobile_layout`에 「꼬리표 끝 ↔ 이름·단계 시작 ≥ PLATE.gap」 6건 추가(예전 빌드 = 0px로 6건 실패).
- 탭 빌드 자리 = 탭 넷 한 줄(겹침 없음 · 심연 둘은 꺼 둠) · 심연을 숨긴 동안 `LayoutTabs(false)`가 둘을 ±109로.

## 7. 위험 · 메이커에서 볼 것
- **UI 아바타 크기·모양**: 44×56 칸에 `PreserveAvatar 1`(비율)로 그린다 — 캐릭터 선택 카드(240×290)와 같은 방식이라 모양은 같아야 하나, 아주 작은 칸에서 아바타가 칸 가운데에 얼마나 크게 들어오는지는 메이커에서만 확인된다(미리보기 그림은 실화면에서 잘라 낸 대역). 작게 보이면 `RANK.avatar`만 바꾸면 된다.
- **아바타 21개 동시**: 칸 20 + 내 줄 1. 기록이 있는 칸만 켜고, 외형이 같으면 다시 입히지 않는다(`CharSelectWindow.Previewed`). 모바일 저사양에서 창 열 때 끊김이 있는지 볼 것.
- 외형 저장소는 새 이름(`rank_looks_c1`) — 첫 배포 땐 모든 줄이 그림자 모습에서 시작해, 각 캐릭터가 기록을 갱신하거나 창을 열면 채워진다.
- 창이 넓어져(바탕 1188) PC 오른쪽 「메뉴」·「일지」 단추를 창이 열린 동안 덮는다(소지품·능력치 창과 같음).
- GameHUD는 생성물 — 통합 때 다른 갈래(SocialWin)의 `tools/build/ui.cjs`와 합친 뒤 다시 만들어야 한다.
