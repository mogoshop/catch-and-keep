## 한 줄 결론

**방식 탓도, 처음 불러오기 탓도 아니다 — 측정 도구 탓이다.** `maker_screenshot`을 부를 때마다 메이커 화면 표시가 약 0.27초씩 멈춘다(게임 논리·타이머는 안 멈춤). 장마다 70~150ms인 장별 효과는 그 멈춤 동안 걸렸다 지워져 화면에 남지 않고, 스틸 간격(0.3~1.1초)도 장 길이보다 길다. 10-31 회차의 「실속도」 판정은 녹화 없이 `maker_screenshot` 스틸만으로 했다(`RUN-log.txt` 3행 「maker_screenshot 스틸만. 녹화 없음.」). 화면 녹화(ffmpeg)로 보면 같은 효과가 실제 시전 경로·첫 사용·새 세션 모두에서 첫 장부터 끝까지 그려진다. → 장별 `PlayEffect` 방식은 그대로 둔다.

조사 중 따로 찾은 것 하나: **그림자 희생 10장이 미리 불러 두기 목록(`SkillEffects.OnBeginPlay`)에서 빠져 있었다**(5종 중 유일). 메이커에서는 이번에 첫 사용 빈 장이 재현되지 않았지만(메이커는 로컬 캐시) 10-31 메테오 L2에서 같은 누락이 「첫 사용 2~7장 1.6~1.8초 빔」을 만든 전례가 있어 한 줄 보강했다(아래 「수정」).

## 원인 정리

1. `maker_screenshot` 한 번에 메이커 화면 표시가 약 0.27초 멈춘다(D1 녹화 정지 구간 223~296프레임이 0.27초씩 0.3초 주기). 게임 논리는 그대로 돈다(T1).
2. 장별 효과는 `Util.PlayFramesPlan`이 시작 시각 기준 타이머로 장을 갈아 끼우므로, 화면이 멈춘 동안에도 장이 걸렸다 지워진다 → 멈춤이 풀렸을 때는 이미 뒤 장이거나 끝났다. 정지 한 장 효과는 남아 있어 스틸에 찍힌다(10-31 「정지 장은 3초 내내 선명」 · 「loopSec 3.0은 선명」과 같은 이유).
3. 10-31 회차 진단(01:24~01:33)은 스틸만 썼고, 스틸 간격도 0.3~1.1초라 장(70~150ms) 수를 셀 수 없었다. `maker_execute_script` 시작이 최대 약 60초 늦는 것도 겹쳐 「호출 직후 스틸」이 효과 전 화면일 수 있었다.
4. 따라서 「느린 재생 ✅ / 실속도 ❌」은 측정 차이다. 실제 속도(녹화)에서는 C1~C5(스틸 없는 회차)·E1 모두 ✅.
