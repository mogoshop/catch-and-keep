# 소환수·몬스터 움직임 동기화 (2026-10-10 정리)

소환수가 "뚝뚝 끊긴다 / 앞뒤로 껌뻑인다 / 그림자가 따로 논다"를 하루 동안 8차례 QA로 고친 결과다.
**이 문서의 「하지 말 것」을 어기면 같은 증상이 바로 재발한다.** `npm test`의 「움직임 불변식」 단계(`tools/check_motion.cjs`)가 핵심 항목을 자동으로 확인한다.

## 1. 결론 — 무엇이 진짜 원인이었나

| 증상 | 진짜 원인 | 해결 (커밋) |
| --- | --- | --- |
| 소환수가 많을수록 서버가 30~74ms씩 멈춤 | 소환수마다 매 프레임 맵 전체 몬스터·소환수 목록을 새로 만들고 버림 (할당·GC) | `Util:ListOf` 0.2초 캐시, 소환수 판단 20Hz (b35c701) |
| 걸을 때 앞뒤로 껌뻑임 | **엔진이 서버 위치가 올 때마다 소환수 루트 위치를 덮어쓴다.** 클라이언트가 루트에 쓴 위치는 그 프레임에 사라진다 (메이커는 매 프레임 덮어써 루트에 쓴 위치가 화면에 아예 안 나왔다) | 루트 그림을 끄고 **맵 아래 클라이언트 전용 대역(MSVis)** 이 그린다 (d57ef56 → c3c4078) |
| 대역을 루트 자식으로 둬도 여전히 껌뻑임 | 자식은 서버가 루트 위치·좌우(Scale.x)·클립을 바꿀 때마다 한 프레임 끌려간다 | 대역을 루트가 아니라 **맵**에 두고 위치·좌우·서기/걷기를 클라이언트가 정함 (c3c4078) |
| 걸을 때 캐릭터보다 덜 부드러움 | 서버 위치를 아무리 잘 이어 그려도 통신으로 띄엄띄엄 오는 값 | 내 소환수의 따라가기는 **내 캐릭터 화면 위치로 매 프레임 직접 계산** (213e128) |
| 멈출 때마다 전사·마법사 앞뒤가 바뀜 | 서버가 평활·예측한 주인 위치가 멈출 때 되돌아가 「반대로 걸었다」고 판단 → 대형 180° 회전 | 주인이 실제로 걷는 동안(OwnerVel > 0.3)의 방향으로만 튼다 (213e128) |
| 걸을 때 전사가 늘 뒤에서 뭉침 | 따라가기 최대 1.3배라 주인보다 느림 | 주인 속도의 1.0~1.6배, 주인 몸은 옆으로 비켜 돎 (`PassOwner`) (d57ef56) |
| 소환 직후·서서 공격 후 대역이 주인 위에 뭉침 | 대형 방향을 클라이언트가 따로 추측 → 서버와 반대면 서버 쪽으로 당기는 힘과 맞섬 | `OwnerFacing`을 동기화(8°↑ 바뀔 때만)하고 클라이언트는 그 값만 쓴다 (41d7e04) |
| 발밑 그림자가 따로 놂 | Kinematicbody가 그리는 그림자는 서버 위치(루트)에 붙어 있음 | 내 화면에서 `EnableShadow=false`, 같은 타원을 대역 아래 픽셀로 (41d7e04) |
| 소환수 주변 모래 네모·로딩 원 | `artsprite` 모델 기본 그림이 모래 바닥(3b9c…), `""`로 비워도 안 지워짐 | 막대는 스프라이트 끔, 몸·원은 생성 즉시 그림 교체 (cce7414) |

## 2. 구조 — 지금 소환수는 이렇게 그려진다

```
서버 ShadowUnit (판정·이동·공격의 진짜 위치, 20Hz 판단)
   │ @Sync: OwnerFacing · FormationIndex · FormationOffset · BaseSpeed · Wander · CommandState · Stand/MoveRUID
   ▼
클라이언트 MotionSmoother (World/MotionSmoother.mlua)
   ├─ 위치 결정
   │    · 소환수 + follow/rally      → FollowLocal/FollowMove: 주인(내 캐릭터·파티원)의 내 화면 위치로 서버와 같은 대형 규칙을 매 프레임
   │                                  (주인별 위치·속도·걷는 방향은 OwnerState가 프레임마다 한 번 계산)
   │                                  서버 위치와 0.8칸↑ 벌어지면 천천히 당김, 2.5칸↑ 즉시 이동
   │    · 그 밖(사냥·공격)           → 서버 위치 보간 (지터에 강한 늦춤·시각 다듬기·별도 그리기 시계)
   │    · 사냥 시작 시 직접 그리기 → 보간으로 초당 2칸 이하로 넘어감
   ├─ LookUnit: 좌우(0.15초 유지돼야 바뀜)·서기/걷기 클립을 화면 움직임으로 결정 (루트는 건드리지 않음)
   └─ PlaceVis: 맵 아래 클라이언트 전용 대역에 그린다
        MSVis (몸) ─┬─ MSVisRing   (발밑 원 = 모델 자식 AllyRing 복제)
                    ├─ MSVisBar    (체력 막대, ShadowUnit.HpBarAlt로 UpdateHpBar가 그림)
                    └─ MSVisShadow (발밑 그림자 타원, ShadowSize × 개체 크기)
        원래 루트의 몸 그림·AllyRing·HpBar·몸체 그림자는 내 화면에서만 끈다
```

판정·피해 숫자·타격 이펙트는 여전히 **서버 위치(루트)** 기준이다. 대역은 그림일 뿐이다.

## 3. 하지 말 것 (재발 방지)

1. **서버가 움직이는 개체의 루트 `TransformComponent.WorldPosition`에 매 프레임 써서 부드럽게 만들려 하지 말 것.** 움직이는 동안 엔진이 덮어쓴다. 보이게 하려면 맵 아래 클라이언트 전용 개체에 그린다.
2. **대역을 서버 개체의 자식으로 두지 말 것.** 서버가 부모의 위치·크기·클립을 바꿀 때마다 끌려간다.
3. **클라이언트가 서버 값(대형 방향 등)을 따로 추측하지 말 것.** 서버와 다르면 「서버 위치로 당기기」와 맞서 뭉치거나 떤다. 필요한 값은 동기화하고 그대로 쓴다.
4. **소환수 서버 판단을 매 프레임으로 되돌리거나, 판단 안에서 `GetChildComponentsByTypeName`으로 맵 전체를 뒤지지 말 것.** `_Util:ListOf(map, type)`를 쓴다.
5. **대형 방향을 평활·예측한 주인 위치의 이동량으로 정하지 말 것.** 멈출 때 되돌아가 180° 돈다. `OwnerVel > 0.3`일 때의 `OwnerVelDir`만 쓴다.
6. **`artsprite`로 만든 클라이언트 개체를 그림 없이 두지 말 것** (기본 모래 바닥). 만들자마자 그림을 넣거나 SpriteRenderer를 끈다.
7. **움직임 확인을 `execute_script` 안의 `ElapsedSeconds` 간격으로 재지 말 것** (벽시계라 흔들림). 프레임 `delta`로 재거나 MotionSmoother의 Stat* 카운터를 쓴다.
8. **이미 시도해 버린 방식으로 돌아가지 말 것** — 서버 위치 앞질러 그리기(추측 항법)는 「날아다닌다」로 폐기(8cb22b2 → 5413d4e).

## 4. 확인 방법 (메이커)

테스트 소환수는 실제와 같게 목록에 넣어야 대형 번호가 갈린다:
```lua
-- server_main
local list = _UndeadSystem:ListOf(p)
local rec = _UndeadSystem:MakeRecord(p, "skeleton", 20, nil)   -- "skeleton" / "mage"
table.insert(list, rec)
_UndeadSystem:SpawnUnit(p, rec, pos, nil, nil)
_UndeadSystem:RefreshSummary(p)
```
클라이언트에서 확인할 값 (2026-10-10 기준):

| 항목 | 기대 | 읽는 법 |
| --- | --- | --- |
| 대역이 원하는 위치에서 벗어난 정도 | 0.07칸 이하 | `r.vis.TransformComponent.WorldPosition` vs `r.dx, r.dy` |
| 서 있을 때 대역과 서버 위치 차이 | 평균 0.1칸 이하 (측정 0.04) | `r.vis` vs 루트 `WorldPosition` |
| 걷기·사냥 15초 순간이동 | 0 | `_MotionSmoother.StatSnap` |
| 따라 걸을 때 한 프레임 최대 화면 속도 | 걷기 속도 수준 (1.6~2.2칸/초) | `StatMaxSpeedLocal` |
| 걷기 3~4초 뒤 전사 위치 | 주인 앞 0.5칸 이상 | 대역 위치 · 주인 진행 방향 내적 |
| 루트 몸 그림·AllyRing·HpBar | 내 소환수 모두 꺼짐 | `e.SpriteRendererComponent.Enable` 등 |

## 5. 남은 일

- **파티원 소환수**: 대역 그리기와 직접 따라가기 모두 적용 (10-10 9차). 주인 = 파티원의 내 화면 위치. 실제 2인 파티로는 아직 확인 못 함 — 같은 코드 경로를 내 소환수로 메이커에서 확인.
- **몬스터**: 아직 루트 위치에 보간을 쓴다 (서버 위치와 차이가 0.1~0.3칸이라 눈에 덜 띔). 거슬리면 같은 대역 방식으로 옮긴다.
- 서버 소환수는 주인 몸을 통과하지 못해 대형 좌우가 바뀔 때 0.5~1칸 어긋날 수 있다 (대역이 천천히 당겨 맞춘다).
