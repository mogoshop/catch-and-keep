## B. ✅ 완료 (메이커 확인)

### B1. 그림자 강화가 너무 셈 (Lv12가 +9 여왕 그림자로 악몽 Lv23을 쓸어버림)

- **원인**
  - 강화 비용이 싸다: +0→+9 누적 정수 **99개** (3, 5, 7, … 19). 강화 +1당 공격·생명 **+6%** → +9면 **+54%**.
  - 보스 그림자는 등급 기본값(3등급)이 이미 높은데 강화도 같은 비율로 붙는다. 레벨 제한이 없어서 Lv12도 +10까지 가능.
  - 그림자 힘은 주인 레벨까지만 내지만(EffectiveLevel), 강화 배율은 그 위에 곱해져 레벨 제한을 사실상 무시한다.
- **수정안 (셋을 함께)**
  1. **강화 상한을 주인 레벨에 묶기:** 최대 강화 = 주인 레벨 ÷ 3 (Lv12 → +4, Lv24 → +8, Lv30 → +10).
  2. **비용 상향 + 등급 배율:** 기본 5 + 강화당 4 (+9 누적 189), 정예 ×1.5, **보스 ×3**.
  3. **보스 그림자 강화 효율 절반:** 보스는 +1당 3% (일반·정예는 6% 유지).
- 이미 +9인 그림자는 그대로 두되, 실제 적용 강화는 상한까지만 (예: Lv12면 +4로 계산). 보관함에 「+9 (적용 +4 · Lv15에 +5)」처럼 표시.
- 확인: `tools/sim.py`로 Lv12 + 여왕 +4 그림자 vs 악몽 Lv16~18 무리 처치 시간이 보통 Lv12 사냥과 비슷한지.

### B2. 두건(잿빛 장막 후드)이 바닥에 너무 크게 떨어짐

- **원인:** 떨어진 장비는 외형 썸네일(`thumbnail://`)을 0.4배로 그린다. 메이플 장비 썸네일은 작지만, 직접 만든 후드는 원본 그림이 커서 0.4배로도 몬스터만큼 크다.
- **수정:** `item_bases.csv`의 `iconPx`(원본 픽셀 크기)를 후드에 넣고, LootDrop이 썸네일이어도 `iconPx`가 있으면 그 크기로 맞추도록 순서를 바꾼다. 후드 썸네일 크기는 리소스 정보로 확인. 소지품 칸 아이콘 크기도 함께 확인.

### B3. 해골 마법사가 해골 전사와 똑같이 생김

- **원인:** 해골 마법사가 해골 전사(`skel_warrior`) 그림을 그대로 쓰고 색만 바꾼다 (UndeadSystem.Raise).
- **수정:** 메이플 리소스에서 **마법을 쓰는 해골/언데드 몬스터 묶음**(서기·공격·이동 애니메이션)을 찾아(`msw-search`) 마법사 전용으로 쓴다. 속성 색 입히기는 유지. 없으면 코덱스 요청서.

### B4. 그림자 보관함이 다른 HUD 아래에 깔림 + 전체 UI 순서 점검

- **원인:** 메이커가 저장하면서 UI 그룹 순서를 다시 매겼고, 그 결과 **그림자 창(ShadowHUD)과 기본 HUD(GameHUD)가 둘 다 5**가 되어 아래쪽 바로가기 줄이 그림자 창 위로 올라왔다.
- **함께 발견한 같은 문제**
  - **확인 창(14)이 캐릭터 선택 창(30)보다 낮다** → 캐릭터 삭제 확인 창이 선택 창 뒤에 숨는다.
  - 보상 알림(RewardHUD 1)이 기본 HUD(5)보다 낮다 → 알림이 HUD에 가려질 수 있다.
  - 순서 값이 겹치는 그룹이 여러 개 있다 (상점·창고·상인·일지가 모두 7이었음).
- **수정:** 모든 그룹에 **겹치지 않는 순서**를 정해 빌드 스크립트와 파일 모두에 반영한다.

  | 층 | 그룹 (순서) |
  | --- | --- |
  | 월드 위 표시 | AimHUD 0 |
  | 상시 HUD | NavigationHUD 2 · CompanionHUD 3 · GameHUD 5 · InteractionHUD 6 · RewardHUD 7 |
  | 창 | ShopHUD 10 · StashHUD 11 · MerchantHUD 12 · JournalHUD 13 · QuestJournalHUD 14 · EquipmentHUD 15 · **ShadowHUD 16** |
  | 설정·전체 화면 | AudioSettingsHUD 20 · CharSelectHUD 30 |
  | 맨 위 | **ConfirmHUD 40** |

  메이커가 다시 매기는지 저장 후 확인하고, 매긴다면 그 규칙(정렬 기준)을 찾아 위 순서가 유지되게 맞춘다. 확인은 창마다 열어서 스크린샷.

### B5. 미니맵이 너무 밝고 전부 보여줌 (보스·피의 제단 위치까지)

- **원인:** 미니맵이 맵 전체 지형과 모든 표시(출구·웨이포인트·보스·의뢰 목표)를 처음부터 그린다. 지형 색도 화면(어두운 시야)보다 밝다.
- **수정 (D2 자동 지도 방식)**
  - 맵을 칸(약 3×3 단위)으로 나눠 **지나간 곳(플레이어 주변 반경 약 5칸)만 밝혀진다.** 밝혀지지 않은 곳은 어두운 안개로 덮는다.
  - 출구·웨이포인트·보스·의뢰 목표 점은 **밝혀진 칸에 있을 때만** 보인다. 의뢰 목표는 「목표: 피의 제단」 글자만 남기고 위치 점은 숨긴다.
  - 미니맵 지형·바탕 색을 지금보다 어둡게 (게임 화면의 어둠과 맞춤).
  - 밝혀진 칸은 접속 중에만 기억한다 (D2처럼). 맵을 다시 들어와도 같은 접속 중이면 유지.
- 확인: 새 맵 입장 → 미니맵이 거의 검고, 걸은 길만 드러나며, 보스 점은 근처에 가야 보임.

### B6. 신발에 이동 속도가 너무 안 붙음

- **원인:** 신발의 이동 속도 옵션(걸음의 10~20%, 질풍의 21~30%)에 장비 수치 배율 0.7과 보통 난이도 상한 0.6이 둘 다 곱해져 실제로는 4~8% 정도만 나온다. 다른 옵션이 많아 이동 속도가 뽑힐 확률 자체도 낮다.
- **수정**
  - 이동 속도(`ms`)는 장비 배율·난이도 상한에서 **제외** (D2에서도 고정 수치형 옵션).
  - **신발 기본 이동 속도** 추가: 짚신 +5% · 견고한 가죽부츠 +10% · 망자의 장화 +15% (`item_bases.csv`에 열 추가).
  - 신발에서 이동 속도 옵션이 나올 가중치를 2배로.
