# 잡으면 내편 — Codex·Claude 역할 분담

2026-10-07 사용자 승인: Codex가 프로젝트를 파악하고 메이커 조작·타일·구조물 배치·화면 검증을 담당한다. Claude는 코드와 데이터 구현을 담당한다.

## 프로젝트 이해

- 네크로맨서가 처치한 몬스터의 혼을 추출하고 그림자 군단을 소환하는 디아블로2풍 탑다운 핵앤슬래시.
- 핵심 루프: 처치 → 혼 추출 → 그림자 수집·소환 → 군단 전투 → 분해·강화·장비 성장.
- 현재 구조: Common·Data → 엔티티별 컴포넌트 → 시스템 Logic → 클라이언트 UI. 서버가 수치·보상·저장을 결정한다.
- 콘텐츠·수치는 `data/*.csv`가 기준. `tools/build.cjs`가 데이터 Logic·모델·맵 기능 엔티티·플레이어 구성·UI를 생성한다.
- 지도: town(잿불 야영지) → map01(피 묻은 황무지) → rotmarsh → execution → gallows → crypt1~3 → queentomb. depth는 별도 인스턴스.
- 보통 10개 + 악몽·지옥 복제 18개 = 28개 맵. 보통 10개는 MapBuilder 확인 결과 모두 RectTile 모드 1, 타일 셀 범위 x=-7~6 / y=-3~4, 112개 셀이다. 파일 수를 지형 완성도로 해석하지 않는다.
- 미술 방향: 공식 MSW 리소스를 바탕으로 어두운 폐허·무덤·화로·보라색 그림자 톤. 초기 설계와 최신 코드의 명칭·범위가 다를 수 있으므로 최신 데이터·코드·실행 결과를 우선 확인한다.

## 동시에 작업할 때

1. 작업 시작 시 대상 맵·파일과 저장/빌드 여부를 정한다. 같은 맵을 메이커와 빌드가 동시에 쓰지 않는다.
2. Codex가 맵을 편집하는 동안 Claude는 맵·모델·UI를 다시 쓰는 빌드를 실행하지 않는다. 독립적인 mLua 작업은 가능하다.
3. Codex는 메이커 저장 후 대상 `.map` 변경 목록과 배치 결과를 정리한다. 기존 Claude의 미커밋 변경을 함께 커밋하지 않는다. 백업/커밋 범위는 해당 작업의 변경만 구분한다.
4. Claude가 빌드를 해야 하면 Codex가 편집·저장 작업을 마친 뒤 진행한다. 빌드 후 플레이 중지 → refresh 2번 → 화면·동선·오류 확인.
5. 새 장식은 빌드 관리 이름과 모델을 피한다. `Gate*`, `Torch숫자`, `Spawner`, `Waypoint`, `DepthEntrance`, `BloodAltar`, 관리 대상 몬스터·NPC 모델은 빌드가 재생성·정리한다. 장식에는 `Decor_` 접두사를 권장하되 이름만으로 보호되는 것은 아니다.
6. 기능 위치는 `data/maps.csv`와 `tools/build/maps.cjs`를 함께 확인한다. 예: 필드 포털 x=-6/+6, 마을 출구 (0,-2.8), 마을 도착 (0,-1.2), 필드 도착 x=-4.6/+4.6. 길·벽은 이 지점을 막지 않게 만든다.
7. 악몽·지옥 맵은 보통 맵을 다시 복제하는 구조다. 기본 지형은 보통 맵부터 완성하고, 복제본에만 넣은 장식은 재빌드에서 사라질 수 있다.

## 검증 기준

- 타일: 올바른 타일셋 표시, 모서리·경계 자연스러움, 길/벽의 이동 가능 설정.
- 구조물: 스폰·포털·NPC·웨이포인트 접근 가능, 플레이어·몬스터와 가림 순서 확인, 통로 막힘·맵 밖 이동 확인.
- 전투 화면: 그림자·적·드롭·이펙트가 구분되고 HUD와 겹치지 않는지 확인.
- 오프라인 검사와 실제 메이커 플레이 결과는 구분한다. 실제 확인하지 않은 기능은 미검증으로 기록한다.
- 오류 전달: 맵·동작·발생 시각·클라이언트/서버 구분·오류 코드·파일/줄·재현 조건을 기록한다.

- 메이커 진입은 기존 홈 클라이언트를 종료한 뒤 공식 웹의 해당 월드 ‘이어서 만들기’로 새 실행해 성공했다.

- `docs/progress.md`의 79점은 기존 문서의 확인 기록이며 Codex가 전체 기능을 재검증한 점수가 아니다.
- 초기 project-rules의 Phase 0 제한과 현재 룬·멀티·심도 코드/최신 구조 사이에 시점 차이가 있다. 범위 확장을 새로 결정한 것으로 해석하지 않는다.

## Codex 도구·지침 적용

- MSW 지침과 빌더는 프로젝트 `.claude/skills/`에 있다. Claude의 `Skill`/`Read` 도구가 없는 Codex는 사용자 승인에 따라 로컬 파일 도구로 읽기 전용 조사한다.
- 사용자가 메이커 조작·타일 배치를 Codex에 맡겼으므로, 기존 문서의 ‘사용자가 직접 메이커를 조작’하는 역할은 이 범위에서 Codex가 수행한다. 메이커 UI를 사용하는 타일 작업이며 배열 직접 편집 승인은 아니다.
- 현재 Codex 세션에는 Maker MCP 전용 도구가 노출되지 않았다. CUA로 메이커 화면을 실제 조작·관찰하며, 전용 MCP 연결/AI 연결 활성화는 아직 확인되지 않았다.
- 구현 작업 전에는 해당 MSW 스킬·참조·현재 API와 버전을 다시 확인한다. 캐시 문서의 고정 버전 숫자를 프로젝트 버전에 강제로 적용하지 않는다.

## 첫 맵 작업 순서

1. Claude의 현재 변환 오류 수정·빌드 여부를 확인하고 편집 가능한 시점을 맞춘다.
2. town과 map01의 타일셋·리소스 등록·화면 표시를 확인한다. 보라/검정 화면의 원인을 검증하기 전 리소스 누락이라고 단정하지 않는다.
3. town의 스폰–상인–노인–웨이포인트–출구 동선을 먼저 만든다.
4. map01의 양쪽 포털을 잇는 길과 전투 공간을 만든다.
5. 저장·화면·이동·포털·NPC 접근을 확인한 뒤 다른 영역과 난이도 복제로 확장한다.
